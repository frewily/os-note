# 领域二 · 请求层（已学 ✅）

## 概念讲解与示例

### requests 核心 API
- 是什么：向服务器发 HTTP 请求、拿回响应对象的库
- 为什么：爬虫第一步是"把网页拿回来"，requests 是 Python 最常用的 HTTP 客户端
- 怎么做：
```python
response = requests.get(url, headers=headers, params={"start": 25}, timeout=(5, 10))
response.raise_for_status()   # 非 2xx 直接抛异常
response.text                 # HTML/JSON 文本
response.content              # 二进制字节（下载用）
```

### 状态码
- 200 成功；**418/403 反爬拦截**（豆瓣裸请求 418，B站 CDN 403）
- `raise_for_status()` 优于 `if response.ok`：失败当场抛异常，在哪错在哪报
- **200 不代表内容正确**：反爬 JS 挑战页也是 200（豆瓣图片 CDN 偶发）——下载前检查 `Content-Type`：图片应为 `image/jpeg`，挑战页是 `text/html`（挑战页靠浏览器执行 JS 种 cookie 后刷新才给真内容，requests 不执行 JS）

### 编码（中文乱码根源）
- `response.encoding` 可能猜错 → 用内容嗅探覆盖：`response.encoding = response.apparent_encoding`

### 超时与伪装
- `timeout=(5, 10)`：连接5s/读取10s，防挂死
- `User-Agent`（伪装浏览器，**默认必加**）、`Referer`（声明来源页，**踩到防盗链再加**）

### 认证方式（Cookie vs Token）
- 登录凭证不止 Cookie 一种，常见：
  | 方式 | 凭证放哪 | 典型场景 |
  | --- | --- | --- |
  | Cookie + Session | 浏览器自动带 | 传统服务端渲染网站（老 Java Web） |
  | Token（JWT） | `Authorization: Bearer xxx` 头 | 前后端分离（Vue/React + Spring Boot 接口） |
  | Basic Auth / API Key | `Authorization` 头 | 开放接口 |
  | OAuth2 | access_token | 第三方登录 |
- 爬虫判断法：DevTools → Network → 看请求 Headers 带的是 `Cookie` 还是 `Authorization`，照抄
- 本质都是"带凭证冒充本人"

### Referer 什么时候加（判断规则）
- 默认只加 User-Agent；**加了 UA 还是 403/418 → 补 Referer**
- URL 域名和来源页面域名**不同**（CDN 如 `img3.doubanio.com`、`upos-...bilivideo.com`）→ 大概率要加
- 浏览器能开、脚本拿不到 → DevTools → Network → 该请求 **Request Headers** 里有哪些头，**照抄关键三个**：User-Agent / Referer / Cookie（Sec-Fetch-* 等浏览器自动头不用抄）
- Referer 填"你在哪个页面点开的"：B站视频 → `https://www.bilibili.com`；豆瓣图片 → `https://movie.douban.com`

## 动手验证
- 任务：不带 UA 请求豆瓣 vs 带 UA，观察状态码差异
- 用户结果：不带 UA → 418；带 UA → 200（已实测）
