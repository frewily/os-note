# 注解

---

## 核心

注解是一种元数据——给代码贴上标签，框架通过读取这些标签来决定怎么处理代码。

---

## 本质

注解不改变代码行为，只提供信息。真正干活的是读取注解的代码（通常是框架）。

```java
// @Override 是一个注解——告诉编译器"这个方法覆盖了父类的方法"
@Override
public String toString() { ... }

// @Service 是一个注解——告诉 Spring "把这个类注册为 Bean"
@Service
public class UserService { ... }

// @Transactional 是一个注解——告诉 Spring "这个方法需要事务"
@Transactional
public void createOrder() { ... }
```

---

## 常见的注解分类

```java
// 1. 给编译器的
@Override          // 检查方法覆盖
@SuppressWarnings  // 忽略警告

// 2. 给框架的（Spring）
@Component         // 注册为 Bean
@Service           // 业务层
@Repository        // 数据层
@Controller        // 控制器
@Autowired         // 依赖注入
@Transactional     // 事务

// 3. 给配置的
@Configuration     // 配置类
@Bean              // 声明 Bean
@Value             // 注入配置值

// 4. 给 API 的
@GetMapping        // GET 请求映射
@PostMapping       // POST 请求映射
@PathVariable      // 路径参数
@RequestBody       // 请求体绑定
```

---

## 注解可以有什么

```java
// 一个完整的注解定义
@Target(ElementType.METHOD)       // 这个注解用在方法上
@Retention(RetentionPolicy.RUNTIME) // 运行时保留（可以通过反射读取）
public @interface Loggable {
    String value() default "";     // 可以带参数，有默认值
    boolean showArgs() default false;
}

// 使用
@Loggable(value = "创建订单", showArgs = true)
public void createOrder(OrderDTO dto) { ... }
```

---

## vibe coding 视角

- 注解是 Spring Boot 的使用核心——不需要理解原理，**能看懂是什么含义就行**
- 补充说明：看到 `@Component` / `@Service` / `@Repository` / `@Controller`，本质上都是注册 Bean。`@Service` 只是语意更明确，实际功能和 `@Component` 一样
- 看到一个不认识的注解，查它的作用即可。注解的组合使用（如 `@SpringBootApplication` 其实包含了三个注解）是常见设计，能意识到这一点就够了

## 项目关联

| 注解 | 在项目中的位置 |
|------|---------------|
| `@Service` | UserService、AIService 等业务类 |
| `@RestController` | 所有 Controller 类 |
| `@GetMapping` / `@PostMapping` | API 接口方法 |
| `@Autowired` | 依赖注入的字段上 |
| `@Configuration` + `@Bean` | 配置类中声明第三方组件 |
| `@Transactional` | 涉及数据库写操作的方法上 |
