# 泛型

---

## 核心

泛型是类型参数化——定义时先用占位符代表类型，使用时再确定具体类型。主要作用是编译期类型检查和消除强制类型转换。

---

## 基本用法

### 无泛型 vs 有泛型

```java
// 无泛型：可以放任何类型，取出时必须手动强转
List list = new ArrayList();
list.add("hello");
list.add(123);
String s = (String) list.get(0);  // 手动强转，类型不对则运行时异常

// 有泛型：限定元素类型，编译器承担类型检查
List<String> list = new ArrayList<>();
list.add("hello");
// list.add(123);      // 编译错误，String 列表不能放 Integer
String s = list.get(0);  // 自动返回 String，无需强转
```

**价值**：将运行时类型错误提前到编译期发现。

### 泛型类

最常见的泛型形式，Spring Boot 中统一返回结果即典型例子：

```java
public class Result<T> {
    private int code;
    private String message;
    private T data;
    
    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.code = 200;
        r.data = data;
        return r;
    }
    
    public T getData() { return data; }
}

// 使用时确定具体类型
Result<User> result = Result.success(new User("张三"));
User user = result.getData();  // 无需强转
```

### 泛型符号约定

```java
<T>   Type（类型）
<E>   Element（集合元素）
<K,V> Key, Value（键值对）
<?>   通配符（未知类型）
```

---

## 通配符

```java
List<? extends User>   // 可以读，不能写（生产者）
List<? super User>     // 可以写，读出来是 Object（消费者）
```

**实际使用**：日常业务代码中很少直接编写通配符语法，多见于框架源码和工具库。阅读时了解基本含义即可。

## vibe coding 视角

泛型是看 AI 生成代码时高频遇到、但自己很少主动编写的语法。

重点关注：
- `List<T>`、`Map<K,V>`、`Optional<T>` 等常见泛型类
- 自定义泛型类或泛型方法出现时，理解其意图（复用、类型安全）
- 接口或类定义中的泛型参数约束关系（如 `T extends Comparable`）
