# 泛型

---

## 一句话核心

泛型就是"先占个位置，等用到的时候再告诉它具体是什么类型"——让代码更安全，不用写一堆强制类型转换。

---

## 为什么用

这是 vibe coding 中**你几乎不需要主动用，但天天能见到**的东西。

你看框架源码、看 AI 生成的代码，到处都是：

```java
List<String>
Map<String, User>
ResponseResult<T>
Optional<User>
```

如果你不懂泛型，看到 `List<String>` 你会想"这个 `<String>` 是干嘛的"——但如果你懂，你就知道它是在说"这个 List 里只能放 String"。

**真正需要你判断的场景**：AI 生成的代码里，如果一段逻辑需要复用但类型不同，它可能会写泛型方法。你要能看懂它的意思。

---

## 关键理解

### 不写泛型 vs 写泛型

```java
// 没有泛型 —— 啥都能放，取出来要自己强转
List list = new ArrayList();
list.add("hello");
list.add(123);
String s = (String) list.get(0);  // 手动强转，类型不对就炸

// 有泛型 —— 说好只能放什么，编译器帮你盯着
List<String> list = new ArrayList<>();
list.add("hello");
// list.add(123);    // 编译不通过，String 列表不能放数字
String s = list.get(0);  // 不用强转，取出来就是 String
```

**本质**：编译时多一层类型检查，运行时被擦掉（泛型擦除）。

### 常见泛型符号（约定俗成）

```java
<T>   Type（类型）
<E>   Element（元素，集合里用）
<K,V> Key, Value（Map 里用）
<?>   通配符（不知道/不关心具体类型）
```

### 通配符 — 你最容易困惑的地方

```java
// 这两个有什么区别？
List<? extends User>   // 可以放 User 及其子类，但只能读不能写
List<? super User>     // 可以放 User 及其父类，可以写进去

// 简单记法：
// extends → 读（生产者，只管往外拿）
// super   → 写（消费者，只管往里放）
```

实际上你在 vibe coding 中**几乎不会自己写通配符**。AI 写的代码里如果出现了，你看一眼大概知道意思就行。

## 代码看一眼

```java
// 泛型类 —— 最常见的泛型
public class Result<T> {
    private int code;
    private String message;
    private T data;  // T 是啥？调用的时候才知道
    
    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.code = 200;
        r.data = data;
        return r;
    }
}

// 使用 —— 调用时指定 T 的具体类型
Result<User> userResult = Result.success(new User("张三"));
//                     ↑ 这里确定了 T = User
User user = userResult.getData();  // 不用强转，直接拿
```

你会发现 Spring Boot 项目里返回给前端的统一结果类，基本都长这样。

---

## 你的项目里

| 场景 | 说明 |
|------|------|
| **统一返回结果** | `Result<T>`，API 返回给前端的数据包裹一层 code + message + data |
| **集合操作** | `List<String>`、`Map<String, Object>`、`Set<Long>` — 日常见得最多的地方 |
| **Optional** | `Optional<User>` — 防止空指针，表示"可能有也可能没有" |
| **自定义泛型方法** | 如果你的项目里有工具类（比如 Redis 工具类），方法和类上大概率有泛型 |
