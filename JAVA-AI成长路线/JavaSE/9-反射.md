# 反射

---

## 核心

反射是在运行时获取类的信息并操作它的能力——不知道具体类名也能创建对象、调用方法、访问字段。

---

## 为什么需要反射

**正常写代码**：编译时就知道操作哪个类。

```java
User user = new User();    // 明确知道：我要 new 一个 User
user.setName("张三");       // 明确知道：User 有 setName 方法
```

**框架面临的问题**：写框架的人**不知道未来会用哪个类**。

```java
// 假如你自己写一个简易框架，想实现一个功能：
// 读取配置文件 "userClass=com.example.User"
// 根据配置动态创建对象

// ❌ 编译时写死类型——做不到，因为还不知道配置里写的是什么
User user = new User();  // 如果明天配置改了，这里得改代码重新编译

// ✅ 反射——运行时才知道类名，也能创建对象
String className = config.getProperty("userClass");  // "com.example.User"
Class<?> clazz = Class.forName(className);            // 加载类
Object obj = clazz.getDeclaredConstructor().newInstance();  // 创建实例
```

Spring、MyBatis、Jackson 等框架全是这么工作的——**编译时不知道你的类名，靠反射在运行时动态操作**。

## 核心 API

```java
// 随便写一个类，用来演示
public class User {
    private String name;
    
    public User() {}
    
    public User(String name) { this.name = name; }
    
    public String getName() { return name; }
    
    private void secretMethod() {
        System.out.println("我是私有方法");
    }
}
```

```java
// ===== 反射操作 =====

// 1. 获取 Class 对象（三种方式）
Class<?> c1 = Class.forName("com.example.User");  // 最常用：从字符串类名
Class<?> c2 = User.class;                          // 编译期已知类
Class<?> c3 = new User().getClass();               // 已有对象

// 2. 创建实例（调用无参构造器）
Object user = c1.getDeclaredConstructor().newInstance();

// 3. 调用方法
Method getName = c1.getMethod("getName");
String name = (String) getName.invoke(user);       // invoke = "执行这个方法"
System.out.println(name);                          // 输出：null

// 4. 操作私有字段
Field field = c1.getDeclaredField("name");
field.setAccessible(true);                         // 让 private 也可以访问
field.set(user, "张三");                            // 给 name 字段赋值
System.out.println(field.get(user));               // 输出：张三

// 5. 调用有参构造器创建对象
Constructor<?> constructor = c1.getConstructor(String.class);
Object user2 = constructor.newInstance("李四");
System.out.println(c1.getMethod("getName").invoke(user2));  // 输出：李四
```

## 一个完整的理解场景

假设 AI 客服项目需要记录每次 API 调用的参数和耗时。传统方式要为每个方法单独写：

```java
// ❌ 每个方法都得写一遍，重复代码
public User getUserById(Long id) {
    long start = System.currentTimeMillis();
    try {
        // 业务逻辑
        return userMapper.findById(id);
    } finally {
        long cost = System.currentTimeMillis() - start;
        log.info("getUserById 耗时：{}ms", cost);
    }
}

public Order createOrder(OrderDTO dto) {
    long start = System.currentTimeMillis();
    try {
        // 业务逻辑
        return orderService.create(dto);
    } finally {
        long cost = System.currentTimeMillis() - start;
        log.info("createOrder 耗时：{}ms", cost);
    }
}
```

用反射 + 动态代理，可以写一个通用拦截器（这就是 Spring AOP 的原理）：

```java
// ✅ AOP 的核心思想——反射让"统一处理"成为可能
// 不需要每个方法写一遍，框架自动帮你做了
// 你的拦截器已经用到了类似的思想：
// preHandle + postHandle 统一处理所有请求
```

**你项目里的 Interceptor 做的就是类似的事**——只不过拦截器作用在 HTTP 请求层面，AOP 作用在方法调用层面。

## 自己动手感受一下

把这段代码贴到你项目里跑一下：

```java
// 1. 随便找个你的 Service 类
Class<?> clazz = UserService.class;  // UserService 换成你项目里的类

// 2. 看看这个类有哪些方法
System.out.println("====== 方法列表 ======");
for (Method method : clazz.getDeclaredMethods()) {
    System.out.println(method.getName() + " → 参数：" + 
        Arrays.toString(method.getParameterTypes()));
}

// 3. 看看有哪些注解
System.out.println("====== 注解列表 ======");
for (Annotation anno : clazz.getAnnotations()) {
    System.out.println(anno);
}
```

这就是 IDEA 的代码提示、Lombok 生成代码、Spring 扫描 Bean——**背后全是反射**。

---

## 反射的代价

- **性能**：比直接调用慢（但框架会缓存 Method/Field 对象，只慢在启动阶段）
- **安全**：可以访问 private，破坏了封装（框架内部用，不让业务代码乱用）

---

## vibe coding 视角

- 反射是理解 **Spring 为什么能自动装配** 的关键
- 日常业务代码很少直接写反射，也不需要写
- AI 生成的工具类（如通用 Mapper、JSON 处理）中可能出现反射，能看懂即可
- 核心要理解的不是"怎么用反射"，而是"为什么框架需要反射"

## 项目关联

| 场景 | 反射在背后做了什么 |
|------|------------------|
| **@Service + @Autowired** | Spring 扫描包 → 反射加载类 → 找到 @Autowired 字段 → 反射注入依赖值 |
| **@Transactional** | 反射读取方法上的注解 → 判断是否需要开启事务 → 生成代理对象 |
| **JSON 序列化** | Jackson 反射读取对象的字段名 → 拼成 JSON 字符串 |
| **Lombok @Data** | 编译期反射操作 AST 语法树 → 自动生成 getter/setter |
