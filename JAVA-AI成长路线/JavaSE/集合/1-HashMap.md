# HashMap

---

## 核心

HashMap 是基于哈希表的 Map 实现，存储键值对，通过 key 的 hash 值定位数据，理想情况下存取时间复杂度 O(1)。

---

## 数据结构

JDK 8 以后采用 **数组 + 链表 + 红黑树**：

```
bucket 数组
┌─────┬─────┬─────┬─────┬─────┐
│  o  │     │  o  │     │  o  │ ...
└─│───┴─────┴─│───┴─────┴─│───┘
  │           │           │
  ▼           ▼           ▼
 Node       Node        Node
  │          │           │
  ▼          ▼           ▼
 Node      Node        Node  ← 链表或红黑树
```

- **bucket 定位**：`(n - 1) & hash`，n 为数组长度（2 的幂次）
- **hash 计算**：`key.hashCode() ^ (h >>> 16)`，高位参与低位计算，减少碰撞
- **碰撞处理**：多个 key 定位到同一 bucket 时，以链表或红黑树存储
- **树化条件**：链表长度 > 8 且数组长度 ≥ 64 时转红黑树；< 6 时退回链表

---

## 核心行为

### 写入（put）

1. 计算 key 的 hash，定位 bucket
2. bucket 为空 → 直接插入
3. bucket 非空 → 遍历链表/红黑树：
   - 找到 key 相同的节点 → 覆盖 value
   - 否 → 追加到链表末尾
4. 插入后检查 size > threshold（容量 × 0.75）→ 扩容为 2 倍

### 读取（get）

1. 计算 key 的 hash，定位 bucket
2. 遍历 bucket 中的链表/红黑树
3. 找到 key 相同的节点 → 返回 value
4. 找不到 → 返回 null

---

## 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 初始容量 | 16 | bucket 数组大小，必须为 2 的幂次 |
| 负载因子 | 0.75 | 空间与时间的折中，达到容量 × 0.75 时扩容 |
| 树化阈值 | 8 | 链表长度超过此值转红黑树 |
| 退化阈值 | 6 | 红黑树节点数低于此值退化为链表 |

---

## 线程安全

HashMap **不是线程安全的**。多线程并发 put 可能导致：

- 数据覆盖：两个线程同时写入同一 bucket
- JDK 7 头插法在扩容时可能形成环形链表（JDK 8 尾插法已修复此问题）

多线程场景需使用 `ConcurrentHashMap`。

---

## vibe coding 视角

- AI 生成的代码中，`HashMap` 是默认的 Map 实现，大多数场景下直接使用即可
- 关注点在于识别**多线程场景下的误用**——看到多个线程访问同一个 HashMap，应替换为 ConcurrentHashMap
- 树化的具体阈值数字、扰动函数细节属于八股范围，vibe coding 中不需要记忆
