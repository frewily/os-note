# 异常体系

---

## 一句话核心

异常分两种——你必须处理的（受检异常）和你可以不处理的（运行时异常）——但实际项目中，你基本上只要关心运行时异常就够了。

---

## 为什么用

AI 生成的代码里，你会看到 `try-catch`、`throws`、`throw new XXXException`。

如果你看不懂这些，就不知道 AI 为什么在某些地方加了 try-catch，在某些地方没加。更严重的是——你不知道哪些异常需要你处理，哪些可以往上抛。

另一个场景：你让 AI 写一段"出错了就返回友好提示"的代码。如果你说不清楚异常处理的意图，AI 可能生成一大坨 try-catch，每个地方都写重复的逻辑。

---

## 关键理解

```
Throwable（能抛的）
├── Error（系统级，不用管）
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── ...
│
└── Exception（程序级，要管）
    ├── 受检异常（Checked，编译强制处理）
    │   ├── IOException
    │   ├── SQLException
    │   └── ...
    │
    └── 运行时异常（RuntimeException，可以不处理）
        ├── NullPointerException
        ├── IllegalArgumentException
        ├── IndexOutOfBoundsException
        └── ...
```

### 哪些你实际需要关心

**Error**：看到了知道什么意思就行，你处理不了。

**受检异常**：AI 生成的代码里如果调了 IO 操作（读文件、网络请求），编译时会要求你加 `try-catch` 或 `throws`。**你不需要记有哪些，编译器会告诉你。**

**运行时异常**：这才是你日常打交道最多的。数组越界、空指针、参数不合法——都在这类里。Java 不强制你处理它们，但你不处理程序就崩。

### 项目中实际的异常处理方式

```java
// 在 Spring Boot 项目里，大多数异常处理长这样：
try {
    // 业务逻辑
} catch (BusinessException e) {
    return Result.error(e.getMessage());  // 业务异常 → 友好提示
} catch (Exception e) {
    log.error("系统异常", e);
    return Result.error("服务繁忙，请稍后再试");  // 未知异常 → 统一兜底
}
```

你不会在每个方法里都写 try-catch。通常是用**全局异常处理器**（`@RestControllerAdvice`）统一处理，这是 Spring Boot 的标准做法，你项目里大概率也有。

## 代码看一眼

```java
// 业务中常见的自定义异常
public class BusinessException extends RuntimeException {
    private int code;
    
    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }
}

// AI 生成的代码可能是这样
public void createOrder(OrderDTO dto) {
    if (dto.getUserId() == null) {
        throw new BusinessException(400, "用户ID不能为空");
    }
    if (dto.getAmount() == null || dto.getAmount().compareTo(BigDecimal.ZERO) <= 0) {
        throw new BusinessException(400, "金额不合法");
    }
    // 正常业务逻辑...
}
```

看懂了吗？当参数不合法时，主动抛一个业务异常，然后被全局处理器捕获，返回给前端一个友好的错误提示。

## 你的项目里

| 场景 | 说明 |
|------|------|
| **AI 客服项目中** | 调用大模型 API 超时 → 抛出异常 → 全局处理器返回"AI 服务暂时不可用" |
| **用户认证** | JWT 过期 → 抛异常 → 拦截器捕获 → 返回 401 |
| **参数校验** | 前端传的参数不合法 → 抛出 BusinessException → 返回 400 + 错误描述 |
| **统一异常处理** | `@RestControllerAdvice` + `@ExceptionHandler` 统一收口，不用在每个 Controller 写 try-catch |
