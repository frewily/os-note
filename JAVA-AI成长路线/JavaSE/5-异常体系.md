# 异常体系

---

## 核心

Java 异常分为受检异常（编译强制处理）和运行时异常（不强制处理），实际项目中大部分时间只关心运行时异常。

---

## 异常结构

```
Throwable
├── Error                系统级错误，无法处理
│   ├── OutOfMemoryError
│   └── StackOverflowError
│
└── Exception            程序级异常，可处理
    ├── 受检异常           编译期强制处理
    │   ├── IOException
    │   └── SQLException
    │
    └── RuntimeException  运行期异常，不强制处理
        ├── NullPointerException
        ├── IllegalArgumentException
        └── IndexOutOfBoundsException
```

### Error

JVM 层面的严重错误，程序无法恢复。看到时了解含义即可，无需处理。

### 受检异常（Checked Exception）

编译器强制要求 `try-catch` 或 `throws`。通常在 IO 操作、数据库连接等场景出现。不需要记忆具体类型，编译器会提示。

### 运行时异常（RuntimeException）

最常见的异常类型。空指针、参数不合法、数组越界等都属于此类。不强制处理，但不处理会导致程序终止。

## 实际处理模式

Spring Boot 项目中，通常采用全局统一处理，而非每个方法都写 try-catch：

```java
// 全局异常处理器
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusiness(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }
    
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "服务繁忙，请稍后再试");
    }
}
```

```java
// 业务层主动抛异常
public void createOrder(OrderDTO dto) {
    if (dto.getUserId() == null) {
        throw new BusinessException(400, "用户ID不能为空");
    }
    // 正常逻辑
}
```

## vibe coding 视角

AI 生成的 try-catch 通常正确，需要关注的是：

- 异常处理粒度：catch 块中是否只是打印日志而没有实际处理
- 自定义业务异常：统一使用 `BusinessException` 而非直接抛 `RuntimeException`
- 全局处理器：项目中是否有 `@RestControllerAdvice` 统一收口

## 项目关联

| 场景 | 说明 |
|------|------|
| **大模型 API 调用超时** | 捕获超时异常 → 全局处理器 → 返回"AI 服务暂时不可用" |
| **JWT 过期** | 拦截器捕获 → 返回 401 未授权 |
| **参数校验失败** | 抛出 BusinessException → 返回 400 + 错误描述 |
| **统一异常处理** | `@RestControllerAdvice` + `@ExceptionHandler` 统一收口 |
