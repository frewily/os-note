# 接口与抽象类

---

## 核心

抽象类定义"是什么"（is-a），接口定义"能干什么"（can-do）。

---

## 接口（Interface）

**定义**：一组方法签名的集合，只声明能力，不提供实现。

```java
public interface Payable {
    void pay(BigDecimal amount);
}

public class Alipay implements Payable {
    @Override
    public void pay(BigDecimal amount) {
        // 具体支付逻辑
    }
}
```

**价值**：解耦调用方与实现方。Spring 中 Service 层的标准模式就是 Interface + Impl。

**vibe coding 视角**：日常开发中接口的使用频率远高于抽象类。跟 AI 描述需求时说"定义一个 XX 接口"，AI 就会生成 interface。看懂 `implements` 关键字即可。

---

## 抽象类（Abstract Class）

**定义**：包含抽象方法和通用实现的类。子类继承后补充差异部分。

```java
public abstract class BaseAuth {
    public void logAttempt(String username) {
        System.out.println(username + " 尝试登录");
    }
    public abstract boolean validate(String token);
}

public class JwtAuth extends BaseAuth {
    @Override
    public boolean validate(String token) {
        // 具体验证逻辑
        return true;
    }
}
```

**价值**：抽取公共代码，避免重复。适合多个类有共同逻辑的场景。

**vibe coding 视角**：抽象类的使用场景较少，大多出现在框架设计层面。普通业务代码中，组合（Composition）比继承更常用。

---

## 选择依据

| 场景 | 选用 |
|------|------|
| 定义能力规范，不关心实现 | 接口 |
| 抽取公共逻辑，子类填空 | 抽象类 |
| 需要多继承能力 | 接口（Java 不支持多继承类） |

---

## 项目关联

| 概念 | 关联位置 |
|------|---------|
| **接口** | `HandlerInterceptor` — Spring 提供的接口，定义了 preHandle / postHandle / afterCompletion |
| **接口** | Service 层的 `XxxService` + `XxxServiceImpl` 模式 |
| **抽象类** | 多个拦截器共用逻辑时，可用抽象类抽取公共代码，子类各自实现具体拦截逻辑 |
