# 多线程基础

---

## 核心

多线程是让程序同时执行多条任务线的机制——一个 Java 程序默认有一个主线程，可以额外创建多个线程并行工作。

---

## 创建线程的方式

```java
// 1. 继承 Thread
class MyThread extends Thread {
    public void run() { 
        System.out.println("继承Thread方式");
    }
}
new MyThread().start();

// 2. 实现 Runnable（推荐）
class MyTask implements Runnable {
    public void run() {
        System.out.println("实现Runnable方式");
    }
}
new Thread(new MyTask()).start();

// 3. Callable + Future（带返回值，可抛异常）
class MyCallable implements Callable<String> {
    public String call() {
        return "异步结果";
    }
}
FutureTask<String> task = new FutureTask<>(new MyCallable());
new Thread(task).start();
String result = task.get();  // 获取返回值

// 4. 线程池（实际项目中最常用的方式）
executor.submit(() -> System.out.println("线程池方式"));
```

**实际使用**：方式 1 很少用，方式 4（线程池）是项目中绝大多数场景的最终选择。

## 线程生命周期（6 种状态）

```
NEW（新建） → RUNNABLE（可运行） → TERMINATED（终止）
                  ↕
            BLOCKED（阻塞）
            WAITING（等待）
            TIMED_WAITING（超时等待）
```

| 状态 | 说明 |
|------|------|
| NEW | 线程创建但未启动 |
| RUNNABLE | 调用 start() 后，可运行（可能正在执行也可能在等待 CPU） |
| BLOCKED | 等待锁（synchronized 没抢到） |
| WAITING | 等待其他线程通知（如 wait()、join()） |
| TIMED_WAITING | 带超时的等待（sleep(3s)、wait(3s)） |
| TERMINATED | 执行完毕 |

## 常用方法

| 方法 | 作用 |
|------|------|
| `start()` | 启动线程 |
| `sleep(n)` | 当前线程休眠 n 毫秒，不释放锁 |
| `join()` | 等待某个线程执行完再继续 |
| `yield()` | 提示 CPU 可以让给其他线程，但不强制 |
| `interrupt()` | 打断线程的等待状态 |

```java
// join 示例：等待子线程完成
Thread t = new Thread(() -> {
    // 耗时任务
});
t.start();
t.join();  // main 线程在这里等 t 执行完才继续
System.out.println("t 已执行完");
```

## 线程通信：wait / notify

```java
synchronized (sharedObj) {
    sharedObj.wait();    // 释放锁，进入等待，直到被通知
    // 被唤醒后重新获取锁，继续执行
}

synchronized (sharedObj) {
    sharedObj.notify();      // 唤醒一个等待线程
    sharedObj.notifyAll();   // 唤醒所有等待线程
}
```

**核心规则**：

- `wait()` 和 `notify()` 必须在 `synchronized` 代码块中调用
- `wait()` 释放锁，`sleep()` 不释放锁
- `notify()` 只唤醒不释放锁，必须等当前同步块执行完才释放

## 线程安全问题

多线程环境下出现数据错误的根因：

```
多个线程同时读写同一共享数据
         +         同时满足
     至少有一个线程在写
         =
    产生不可预期的结果
```

**解决方案**：

| 方案 | 适用 |
|------|------|
| synchronized | 互斥访问 |
| volatile | 单一变量的可见性 |
| Lock | 灵活锁控制 |
| 原子类（AtomicInteger） | 单变量原子操作 |
| 线程封闭（ThreadLocal） | 数据不共享 |

## vibe coding 视角

- AI 生成的代码中，线程创建和基本的多线程操作通常正确
- 重点关注 `wait/notify` 的配对使用——这是容易出错的地方，通常建议用 `Lock` / `Condition` 替代
- `Future + Callable` 在需要异步获取结果的场景中经常出现，理解其模式即可
- 99% 的场景下，**线程池是比手动创建线程更优的选择**
