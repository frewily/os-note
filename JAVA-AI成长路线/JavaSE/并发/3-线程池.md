# 线程池

---

## 核心

线程池管理一组可复用的线程，避免频繁创建销毁线程的开销。

---

## 7 个核心参数

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数——池中常驻线程数量
    maximumPoolSize,   // 最大线程数——池中允许的最大线程数量
    keepAliveTime,     // 空闲存活时间——超过核心数的线程空闲多久后被回收
    unit,              // 存活时间的单位
    workQueue,         // 任务队列——当核心线程都在忙时，新任务放这里排队
    threadFactory,     // 线程工厂——创建线程的方式（命名、优先级等）
    handler            // 拒绝策略——队列满了也达到最大线程数时怎么办
);
```

---

## 工作流程

```
新任务提交 →
  ① 线程数 < corePoolSize     → 创建新线程执行
  ② 线程数 ≥ corePoolSize     → 放入 workQueue 排队
  ③ 队列满了                  → 创建新线程直到 maximumPoolSize
  ④ 已达 maximumPoolSize     → 执行拒绝策略
```

---

## 4 种拒绝策略

| 策略 | 行为 |
|------|------|
| AbortPolicy（默认） | 抛 RejectedExecutionException |
| CallerRunsPolicy | 谁提交的任务谁自己执行（提交任务的线程执行） |
| DiscardPolicy | 静默丢弃，不抛异常 |
| DiscardOldestPolicy | 丢弃队列中最老的任务，再尝试提交 |

---

## 线程池大小估算

```java
// CPU 密集型任务（计算为主）
poolSize = CPU核心数 + 1

// IO 密集型任务（等待 IO 为主）
poolSize = CPU核心数 × 2
```

**实际开发中**：上述公式只作为起点，最终大小应根据压测结果调整。

---

## 使用建议

- **不要用 Executors 的快捷方法**（如 `Executors.newFixedThreadPool()`），它们可能使用无界队列（`LinkedBlockingQueue`），任务积压时可能导致 OOM
- **手动创建 ThreadPoolExecutor**，明确指定参数
- **给线程池命名**，方便排查问题

```java
// 推荐的创建方式
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    4,
    8,
    60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(1000),
    new ThreadFactoryBuilder().setNameFormat("ai-chat-%d").build(),
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```

## vibe coding 视角

- 线程池是并发模块中最核心的知识点——项目中直接用到，面试中也高频出现
- AI 可能会用 `Executors.newFixedThreadPool()` 创建，需要审查并替换为手动创建方式
- 重点关注核心参数含义和拒绝策略的选择

## 项目关联

| 场景 | 说明 |
|------|------|
| **AI 客服并发请求** | 大模型 API 调用使用线程池管理，避免线程无限制创建 |
| **异步操作** | 日志记录、消息推送等不需要同步返回的操作放入线程池执行 |
| **定时任务** | 定时刷新缓存的线程池管理 |
