# 第三讲：硬件视角的操作系统

> 课程：JYY《操作系统》(2026)  
> 讲义：[硬件视角的操作系统](https://jyywiki.cn/OS/2026/lect3.md)  
> 关联：第二讲从应用侧看到“计算 + 系统调用”；本讲从硬件侧解释，OS 为什么有能力接管程序、响应设备，并在开机时出现。

## 一句话主线

**硬件并不知道“操作系统”这个概念：它只是按规则执行指令、与设备交换数据，并在中断到来时强制跳转。OS 是利用这些硬件机制运行起来的一段特权程序；初始化完成后，它主要在系统调用或中断发生时提供服务。**

```text
硬件提供机制：执行指令 / I-O / 中断 / reset / 特权
                         ↓
OS 利用机制：管理程序和设备、提供 syscall 服务
                         ↓
应用程序：普通计算 + syscall 请求服务
```

## 1. 先把“硬件”理解成状态机

第二讲说“程序是状态机”；从更低一层看，**CPU 也是状态机**。

- **状态**：寄存器和内存中的值；其中 **PC（程序计数器）** 表示下一条要执行的指令地址。
- **初始状态**：CPU 收到 `reset`（复位）后，进入硬件规定的状态；PC 被设置为一个约定地址。
- **普通状态迁移**：CPU 从 PC 指向的位置取出指令，译码并执行；执行结果改变寄存器、内存和下一条指令的位置。

```text
PC 指向一条指令
       ↓ 取指、译码、执行
寄存器 / 内存 / PC 变成新状态
       ↓
继续执行下一条指令
```

例如 `add`、`mov`、跳转等指令只是在这个状态机内改数据。硬件不关心上面运行的是 Linux、Windows、一个裸机小游戏，还是根本没有 OS 的程序；它只认自己支持的**指令集（ISA）**。

注：ISA 是 CPU 能执行哪些指令的规范，或则说是CPU 能理解的指令规则。

> 不要把 PC 想成很可怕的硬件名词：它只是在回答“CPU 此刻该执行哪一行机器指令”。

### 抽象：上下层不必知道彼此的复杂细节

指令集是硬件给上层的接口：上层只需知道 `add`、读设备、触发系统调用等指令的效果，不必知道芯片内部怎样用电路实现。对应地，系统调用也是 OS 给应用的接口：应用只需请求 `read`、`write` 等服务，不必知道设备驱动的细节。

```text
应用生态（复杂）
       ↕ syscall：小而稳定的接口
操作系统与驱动（复杂）
       ↕ ISA：小而稳定的接口
硬件电路与设备（复杂）
```

这解释了为什么同一个 `printf`，既可以输出到屏幕，也可以通过重定向写进文件：应用只是在请求 `write`；具体写到哪个对象，由 OS 根据文件描述符等信息决定。

## 2. 硬件怎样接触真实世界：I/O

CPU 内部的寄存器、内存状态不足以表示鼠标移动、键盘按键、网卡收到数据或灯亮灭。设备通过电路连接到计算机，硬件提供 **I/O（输入/输出）** 机制让指令能与外界交换数据：

- **输入（input）**：把设备或物理世界的信息读入计算机状态，例如读键盘、网卡或摄像头数据；
- **输出（output）**：把计算机状态的结果送给设备，例如显示画面、发网络包、控制 GPIO 引脚电平。

可以先把设备想成“能被读写的外部状态”。具体端口、总线和寄存器的细节以后再学；此刻只需知道，**I/O 让状态机不再是封闭的，而能与物理世界交互。**

## 3. 中断：OS 不会被死循环的应用永远困住

如果 CPU 只能机械地顺序执行指令，应用执行 `while (1) {}` 时就再也轮不到 OS 处理键盘、网络或其他程序了。解决机制是 **中断（interrupt）**：外部设备可以向 CPU 发信号；在允许响应中断时，CPU 会暂停当前执行流，跳到预先约定的处理代码。

```text
应用正在运行（即使它在死循环）
              ↓  时钟 / 键盘 / 网卡等事件到来
CPU 保存必要现场，跳转到 OS 的中断处理代码
              ↓
OS 处理事件、调度等工作，再决定之后做什么
```

- **时钟中断**：周期性到来，是 OS 能重新获得 CPU、实现多任务调度的重要基础；
- **设备中断**：例如键盘按下、网卡收到包，通知 CPU“有事需要处理”；
- **可屏蔽中断**：OS 在极少量关键代码中可暂时关闭；普通应用没有此权限，否则它就能霸占 CPU。

这就是 OS 的“底气”：应用并非自愿把 CPU 还给 OS，硬件的中断机制可以强制让 OS 获得控制权。反过来，如果内核关闭中断后陷入死循环，整台机器确实可能卡死；长按电源键触发的 `reset` 则是更底层的强制恢复手段。

## 4. 系统调用和中断：都是 CPU 进入 OS 的入口

它们都能让 CPU 从应用代码转到 OS 代码，但来源不同：

| 机制 | 谁触发 | 直觉理解 | 例子 |
| --- | --- | --- | --- |
| 系统调用（syscall） | 当前应用主动执行特殊指令 | “我请求 OS 帮我办事” | `read`、`write`、`exit` |
| 中断（interrupt） | 外部硬件/时钟异步发信号 | “外界有事，CPU 必须处理” | 按键、网卡数据、时钟到点 |

进入 OS 后，CPU 还会切换到能执行特权操作的状态。于是应用不能自行关闭中断、随意控制设备或破坏别的程序；它必须经由 syscall 请 OS 代办。

> 以后遇到“陷阱（trap）”“异常”等词，先抓共同点：它们都是让 CPU 从当前代码切换到某段由 OS 接管的处理代码的机制；精确分类会在后续课程展开。

> syscall：程序找 OS。
> interrupt：硬件找 OS。

## 5. 多处理器为什么让 OS 更难

现代电脑/手机通常有多个 CPU 核。概念模型是：

- 每个 CPU 核有自己独立的寄存器和 PC；
- 多个 CPU 核共享同一片主内存；
- 任一时刻可理解为“选某个 CPU 执行一步”，同时每个 CPU 又可能响应中断。

```text
CPU 0：自己的寄存器、PC ─┐
CPU 1：自己的寄存器、PC ─┼→ 共享内存
CPU 2：自己的寄存器、PC ─┘
```

单核顺序程序的下一步通常较确定；多核加上中断后，下一步可能是不同核先运行，也可能先发生外部事件。多种交错顺序会造成并发问题，也正是后续“并发/调度/同步”内容困难的来源。现在不必解决它，只要记住：**多个核共享数据、执行顺序不唯一。**

## 6. OS 从哪里开始运行：reset → firmware → OS

断电后，普通内存（DRAM）会丢失内容，因此 CPU 复位时不能直接从内存里找到 OS。启动链需要一段保存在非易失性存储中的代码：**固件（firmware）**，传统 PC 常称 BIOS，现代机器常见 UEFI。

```text
按下电源 / reset
       ↓
CPU 进入规定初始状态，从规定地址开始取指
       ↓
固件运行：初始化硬件、寻找可启动设备
       ↓
启动引导器（boot loader）把 OS 从磁盘等设备装入内存
       ↓
跳转到 OS 入口；OS 初始化后开始提供 syscall / 中断服务
```

- **固件不是 OS**：它的任务是把机器从“刚复位、内存还没有 OS”带到“OS 已被加载并可运行”。
- **OS 也是代码**：启动后它先初始化设备、内存和处理器；日常运行时并非一直占着 CPU，而主要在系统调用、中断等事件到来时执行服务代码。
- 固件处于启动链很前面，所以若被恶意篡改，机器甚至可能无法正常启动。课堂的 CIH 例子用于说明这条信任链与安全风险，并非要求掌握病毒细节。

### 历史例子：早期 BIOS 的简单约定

传统 BIOS 会扫描启动设备；若发现某设备第一个扇区末尾是启动签名 `0x55AA`，就把该 **512 字节引导扇区** 加载到内存的约定地址（经典 x86 BIOS 中常为 `0x7C00`）并跳转过去。扇区中的 boot loader 再继续加载更大的 OS。

这个例子最重要的不是记地址或魔数，而是理解：**开机不是魔法，只是一段代码按约定加载并跳转到下一段代码。** 现代 UEFI 的实现更复杂，基本思路仍相同。

## 7. 怎样验证而不是只相信：观察状态变化

课堂用模拟器和调试器展示启动过程。一个很有用的概念是 **watchpoint（观察点）**：当某个内存位置或变量被改变时让调试器停下。

例如，为引导扇区将要被加载的内存地址设 watchpoint，就能观察到固件何时把磁盘数据写入该位置；为 OS 入口设 breakpoint（断点），就能确认什么时候跳入下一段代码。

这与第二讲 `strace` 的方法一脉相承：

- `strace` 观察“应用向 OS 发起了什么请求”；
- 模拟器、寄存器查看和 watchpoint 观察“机器状态究竟怎样变化”。

遇到“不理解某个系统故事”时，优先问：**我能观察哪个状态？在哪个时刻它会变化？**

## 8. 本讲对零硬件基础的最低要求

不需要记 CPU 电路、汇编编码或 BIOS 细节。先牢牢记住以下五句话就够了：

1. CPU 是执行指令的状态机，PC 表示下一条指令的位置。
2. 硬件不认识 OS；OS 只是利用硬件机制运行的一段特权代码。
3. I/O 让计算机读写物理世界；中断让 OS 即使面对死循环应用也能重新获得控制权。
4. syscall 是应用主动找 OS；中断多半是外界主动通知 CPU。
5. 开机由 firmware 从 reset 开始，逐步把 OS 加载到内存并跳转给它。

## 9. 课后 40 秒复述

从硬件看，计算机是由寄存器、内存和 PC 构成的状态机：CPU 不断取指、译码、执行，硬件并不知道上面是否运行 OS。硬件通过 I/O 与物理设备交互，又通过中断在时钟或设备事件发生时强制跳转，使 OS 不会被死循环应用永久困住。OS 是一段有特权的普通程序：应用用 syscall 主动请求它，设备用中断让它处理事件。多核系统中每个核有自己的寄存器但共享内存，因此执行交错不唯一。开机时 CPU 从 reset 的约定状态启动，firmware 初始化机器、加载 boot loader 和 OS；OS 初始化后主要成为系统调用与中断的服务提供者。

## 10. 自测题

1. 用“状态、初始状态、状态迁移”描述 CPU 执行程序。
2. 为什么说硬件“不知道有没有 OS”？指令集这一层抽象解决了什么问题？
3. 如果没有中断，一个死循环应用会造成什么问题？时钟中断对 OS 有什么意义？
4. syscall 与中断都能进入 OS；二者在触发来源上有什么根本不同？
5. 为什么普通应用不能关闭中断或任意控制设备？
6. 解释从按下电源到 OS 开始工作的启动链，并说明 firmware 与 OS 的区别。
7. 多核系统中，哪些状态是每个 CPU 核独有的，哪些通常共享？为什么它让程序更难理解？

### 参考答案

> 先脱稿回答，再用答案核对因果关系；能说清主线即可，不必背寄存器名和地址。

1. **状态**包括寄存器和内存中的值，PC 指出下一条指令的位置。CPU 收到 reset 后进入硬件规定的**初始状态**，PC 被设到约定位置。每执行一条指令，就按指令集规则改变寄存器、内存或 PC，形成一次**状态迁移**。

2. 硬件只按 ISA 规定执行指令，不能辨认某段机器码是 OS、浏览器还是游戏。指令集把“上层想做什么”与“芯片内部怎样实现”隔开：上层按指令语义编程，硬件可独立更换或优化实现。

3. CPU 会一直执行死循环，若没有额外机制，OS 无法处理键盘、网络或切换其他任务。时钟中断会周期性打断当前执行流，让 OS 获得运行机会，从而进行事件处理和调度。

4. syscall 是**应用主动**执行特殊指令，请求 OS 服务；中断通常由**外部设备或时钟异步**发起，通知 CPU 处理事件。两者都会使 CPU 跳转到 OS 的处理代码。

5. 关闭中断或直接操作设备会影响整台机器和其他程序；若普通应用有该权限，它能长期霸占 CPU、越权读写设备或破坏隔离。硬件的特权机制只允许 OS 的特权代码执行这些操作。

6. 按电源或 reset 后，CPU 先从规定地址执行非易失存储中的 firmware；firmware 初始化必要硬件、寻找启动设备，运行/加载 boot loader；boot loader 再把 OS 装入内存并跳转到 OS 入口。firmware 负责“把机器带到能启动 OS 的状态”，OS 则在之后管理资源并向应用提供长期服务。

7. 每个核各自拥有寄存器和 PC；它们通常共享主内存。多个核可能以不同顺序读写同一数据，并且还可能被中断打断，因此同一程序的执行交错不止一种，推理和排错更复杂。
