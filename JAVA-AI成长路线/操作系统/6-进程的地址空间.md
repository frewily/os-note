# 第六讲：进程的地址空间

> 课程：JYY《操作系统》(2026)
>
> 讲义：[进程的地址空间](https://jyywiki.cn/OS/2026/lect6.md)
>
> 衔接：第五讲说“进程是一份正在运行的状态”；本讲追问其中最重要的一部分——进程能看到、使用的内存是什么样的，又是谁准备的？

## 一句话主线

**操作系统为每个进程建立自己的地址空间，让程序通过指针访问其中的代码和数据，同时规定哪些地址可读、可写或可执行。`execve` 建立新程序的初始布局；`mmap` 等接口让进程在运行中增减或调整映射。**

## 先用一个直觉理解

把地址空间想成进程自己的“地址簿”：地址 `0x...` 告诉 CPU 要访问哪里，但这只是**进程看到的虚拟地址**。操作系统与硬件一起决定该地址有没有对应的内存、对应什么，以及允许读、写还是执行。

```text
进程 A 的指针 → 进程 A 的地址空间 ─┐
                                   ├→ 硬件在 OS 设置的规则下访问内存
进程 B 的指针 → 进程 B 的地址空间 ─┘
```

因此，两个进程即使使用相同的虚拟地址，也不意味着读到同一份数据。通常各看各的；只有 OS 明确设置共享映射等机制时，才可能共同访问同一份内容。

## 1. 从第五讲的进程模型出发

第五讲的 CrazyOS 用一个结构保存某个进程的 CPU 状态和一块 `mem` 数组。它是教学模型：每个被模拟的进程都有一份“能访问的内存”。本讲把问题转到真实系统：**这份内存如何组织和管理？**

这里先区分两件事：

- **地址空间**：进程能使用的虚拟地址及其映射规则；
- **物理内存**：机器上的真实内存资源。

地址空间并不是一整块已经分配好的物理内存。里面可以有空洞，某些区域尚未实际分配物理页；进程第一次访问时，OS 才可能补上实际内存。MMU（内存管理单元）是硬件中的地址翻译机制，OS 为它设置规则。现在把 MMU 理解成“按 OS 的映射表翻译并检查地址”即可，不需要先学电路或页表细节。

## 2. 指针到底指向什么？

在 C 程序里，指针保存一个地址。对指针进行读取或写入时，CPU 会尝试访问**当前进程地址空间**中对应的位置。

```c
int x = 10;
int *p = &x;
*p = 20;  // 请求写入 p 指向的地址，x 因而变成 20
```

能否访问不只取决于这个数字看起来像不像地址，还取决于该位置是否存在有效映射，以及映射权限：

| 权限 | 含义 | 常见用途 |
| --- | --- | --- |
| `r` | 可读 | 常量、部分文件映射 |
| `w` | 可写 | 变量、堆、栈 |
| `x` | 可执行 | 程序指令 |

访问未映射地址，或在只读区域写入，都可能触发错误并使程序终止。`volatile` 只能要求编译器保留某些读写操作；**它不会让非法地址变得安全或可访问**。

> 重要直觉：内存里的字节本身没有“这是整数/代码”的标签。程序如何解释这些字节由指令和数据类型决定；能否读写或执行，则由地址空间映射和权限约束。

## 3. 一个进程的地址空间里通常有什么？

下面是便于理解的示意，布局和具体地址因系统、程序及随机化而异：

```text
代码区       程序的机器指令，通常可读、可执行
只读数据     字符串常量等，通常只读
数据/BSS     全局变量、静态变量；BSS 启动时清零
堆           动态申请的内存，如 malloc 获得的对象
文件映射区   文件内容、共享库、匿名映射等
栈           函数调用、局部变量、启动参数等
（中间还可能有未映射的空洞）
```

“代码、数据、堆、栈”是对**不同用途区域**的称呼，不是四根物理内存条。它们都出现在进程自己的地址空间里，但有不同的来源和权限。

### `execve` 后的初始内容从哪里来？

第五讲知道 `execve` 会把当前进程换成另一份程序。现在可以追问：换完后，进程如何知道自己的代码、变量和 `main` 参数在哪？

1. **编译和链接**生成可执行文件，文件中描述需要加载的代码、数据等区域及布局要求。
2. **OS 加载器**根据可执行文件和系统约定建立映射、设置权限；需要清零的区域被安排为初始零值。
3. **启动约定（ABI）**规定部分初始寄存器、栈内容等；`argc`、`argv`、环境变量由此传到程序启动代码，再到 `main`。

所以进程启动时的每个有意义的字节都有来历：或来自可执行文件，或按约定清零，或来自参数与环境，或在运行中由程序自己写入。讲义给出的 `PT_LOAD`、System V ABI 是追查细节的入口；现在不需要记字段和寄存器表。

## 4. 运行中如何取得更多内存：`mmap`

程序运行后会产生新的数据，初始布局不够用。OS 提供地址空间管理接口；本讲重点是 `mmap`：在进程地址空间中建立一段映射，并指定长度、来源及访问权限。

常见的两种来源：

- **匿名映射**：没有对应的普通文件，常用于申请内存；
- **文件映射**：把文件内容映射到地址空间，让程序像访问内存一样访问文件的一部分。

相关接口还有 `munmap`（取消映射）、`mprotect`（修改映射权限）；较早的 `brk/sbrk` 也与调整可用内存有关。此时只要能说出它们各自**改变了地址空间的什么**，不需要背完整参数列表。

### `mmap` 和 `malloc` 不是同一层

`malloc` 是应用使用的 C 库函数，负责给程序分配合适大小的内存块。它可以先向 OS 申请较大的区域，再切成小块交给程序；向 OS 取得区域时可能使用 `mmap`，也可能使用 `brk` 等机制，具体取决于实现和场景。

```text
程序：malloc(100)
  → 内存分配器：从自己管理的区域找一块
  → 区域不够时：向 OS 申请或调整映射（如 mmap/brk）
```

`mmap` 返回成功表示虚拟地址范围已建立映射，并**不保证整段物理内存立即到位**。某些页会在首次访问时才由 OS 分配或装入。这就是“申请很大一段空间似乎瞬间完成”的原因之一，但后续实际访问仍会耗费内存和时间。

## 5. 隔离、共享和受控观察

地址空间首先让普通进程难以直接读写其他进程的私有内存。这是隔离和保护的基础；它也让每个程序可以按自己的地址布局运行。

隔离不是绝对禁止任何协作：

- 进程可以按 OS 提供的机制建立**共享内存**；
- 调试器在获得相应权限后，可以查看或修改目标进程的状态；
- `mmap` 可以把文件内容映射给一个或多个进程使用。

讲义后半用游戏金手指、内存搜索等故事说明“找到某个地址并观察其变化，就能反推程序状态”。这是地址空间的应用例子。现阶段理解**映射、权限、隔离和受控访问**即可，不必学习具体游戏修改或硬件劫持技巧。

## 6. 一次安全的小观察

如果有 Linux 环境，可以先看一个进程的地址空间布局：

```bash
cat /proc/self/maps
```

其中每行通常对应一段映射，能看到地址范围、权限和可能关联的文件。建议只做三个观察：

1. 找到至少一段可执行区域与一段可写区域；
2. 找到 `[stack]`；
3. 看看共享库或可执行文件的路径是否出现在映射中。

这份输出只说明**当前进程的虚拟映射**，不要把地址差直接算成“已经占用的物理内存”。当前若只用 macOS，先看课程演示即可；`/proc/self/maps` 是 Linux 接口。

## 8. 40 秒脱稿复述

第五讲说进程是一份运行状态，第六讲展开其中的内存。每个进程看到自己的虚拟地址空间，指针访问的是这个空间里的地址；OS 和 MMU 决定地址映射到哪里、能否读写或执行。代码、数据、堆、栈都在其中，但用途和权限不同。`execve` 根据可执行文件和启动约定建立新程序的初始布局；运行中程序可以通过分配器获取内存，而分配器再用 `mmap` 等机制向 OS 要地址空间。映射不一定立即占用等量物理内存，进程之间默认隔离，也可通过受控机制共享或调试。

## 9. 自测题

请先不看答案回答，答不清时回到对应小节。

1. 为什么两个进程使用相同的指针数值，通常读到的却不是同一份数据？
2. 地址空间与物理内存分别是什么？`mmap` 一大段空间后，物理内存一定立即全部分配了吗？
3. 进程中的代码、全局变量、堆对象、局部变量通常分别位于什么用途的区域？
4. `execve` 后新程序的代码、初始数据、命令行参数分别从哪里来？
5. `malloc` 和 `mmap` 分别是谁提供的？它们是什么关系？
6. 一个指针指向只读区域时尝试写入，为什么可能失败？`volatile` 能让它成功吗？
7. 进程地址空间隔离后，为什么调试器仍有可能观察另一个进程？

### 参考答案

1. 指针保存的是当前进程使用的虚拟地址。不同进程通常有不同映射，同一个数值可对应不同内容；只有明确设置共享等机制时才可能指向同一份底层内容。
2. 地址空间是进程可使用的虚拟地址及映射规则；物理内存是机器的真实资源。建立映射不意味着所有页面立即占用物理内存，实际分配可能延迟到首次访问。
3. 指令通常在代码区，全局/静态变量在数据或 BSS 区，动态申请的对象常在堆或其他分配器管理的映射区，函数调用和局部变量常使用栈；编译器也可能把某些局部值只放在寄存器中。
4. 代码和部分初始数据依据可执行文件加载；零初始化区域按约定获得零值；参数和环境由 `execve` 的调用者提供，并按 ABI 的启动约定传给新程序。
5. `malloc` 是 C 库的分配接口，`mmap` 是向 OS 建立内存映射的接口。分配器可能通过 `mmap` 或 `brk` 获取较大区域，再管理和分配小块。
6. OS 和硬件为映射设置了权限，只读区域不允许写。`volatile` 影响编译器怎样处理访问，不改变映射权限，也不保证访问有效。
7. OS 可以给具备适当权限的调试器提供受控的进程检查机制。隔离针对普通进程的直接访问，并不排除 OS 授权的观察和共享。
