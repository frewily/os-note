# 第五讲：程序和进程

> 课程：JYY《操作系统》(2026)
>
> 讲义：[程序和进程](https://jyywiki.cn/OS/2026/lect5.md)
>
> 衔接：第二讲把程序看成状态机；第三讲说明 OS 是运行在硬件上的程序。本讲开始回答：OS 怎样让多个程序各自运行？

## 一句话主线

**程序是静态的执行规则；进程是程序正在运行时的一份状态。操作系统为每个进程保存运行状态，并用 `fork`、`execve`、`wait`、`exit` 等接口管理它的一生。**

```text
可执行文件（静态）
       ↓ OS 加载、创建运行状态
进程（动态）：代码 + 当前内存/寄存器 + OS 管理的信息
       ↓
运行、创建子进程、换程序、等待、退出
```

## 1. 为什么需要“进程”这个抽象？

一台物理计算机上可以同时打开终端、浏览器和编辑器。每个程序似乎都有自己的内存和执行位置，仿佛独占一台计算机。这是 OS 提供的**虚拟化**：把一台物理机器包装成多个彼此隔离的运行环境。

先沿用第二讲的状态机模型：运行一个程序，至少需要知道它的内存、寄存器以及 PC（下一条指令的位置）。如果 OS 保存多份这样的状态，就可以让不同程序轮流在 CPU 上推进。

讲义中的 CrazyOS 用“选一个程序，执行一步”演示这一想法。真实 OS 不会每条指令都由软件模拟，而是让某个进程在真实 CPU 上运行一段时间，再在适当时机切换。这里先抓住概念：**进程是 OS 管理的一份运行中状态，不是一份磁盘文件。**

## 2. 程序和进程：最容易混淆的一对概念

| 名词 | 直觉 | 例子 |
| --- | --- | --- |
| 程序/可执行文件 | 描述从哪里开始、有哪些指令和初始数据 | 磁盘上的 `/bin/ls` |
| 进程 | 一次正在进行的执行，有自己的当前状态 | 正在运行的某个 `ls`，有自己的 PID |

同一个程序可以启动多次，产生多个不同进程。它们最初可能很相似，但运行后各自的变量、执行位置和结果可以不同。

除了程序自身的状态，OS 还要为进程保存一些管理信息，例如进程号（PID）、父进程号（PPID）、当前工作目录、打开的文件、身份与权限等。这些信息不在可执行文件里，也不一定能直接从程序变量中看到。Linux 的 `/proc/<pid>/` 会暴露不少进程信息，`getpid()`、`getppid()` 等接口也能查询其中一部分。

> 此时不必背所有进程字段。先记住“我的代码运行到哪儿”与“OS 怎样管理我”是两类状态。

## 3. `fork()`：从一个进程变成两个

UNIX 选择了一种很特别的创建方式：`fork()` **复制当前进程**。可以想成对正在运行的状态机拍一张快照，然后让父、子两份状态分别继续运行。

```c
pid_t pid = fork();
if (pid == -1) {
    // 创建失败
} else if (pid == 0) {
    // 子进程
} else {
    // 父进程：pid 是子进程的进程号
}
```

理解 `fork` 最重要的四件事：

1. `fork()` 调用前只有一个进程，成功后有父、子两个进程。
2. 两者都从 `fork()` **返回之后**继续执行；并不是子进程从 `main` 重新开始。
3. 子进程看到返回值 `0`；父进程看到子进程 PID，因此相同代码可以走不同分支。
4. 父、子有各自的内存视图；之后一方修改普通变量，不会直接改掉另一方的变量。

“复制整份内存”是理解语义的好模型。实际系统通常用**写时复制（copy-on-write）**避免创建时真的拷贝每一页内存。另一方面，打开的文件描述符也会被继承，但其背后的打开文件状态可能由父子共享；所以“两个进程完全互不相关”也不对。

### 用小例子追踪进程数

```c
for (int i = 0; i < 2; i++) {
    fork();
}
```

假设两次调用都成功：第一次后有 2 个进程；这 2 个进程都会进入第二轮，各自再复制一次，最后有 4 个进程。追踪时别只盯着“源代码里有两次循环”，要数**每一步有多少个进程正在执行这行代码**。

课堂还用 `fork` 展示并行搜索、预处理后共享初始状态，以及失控创建进程的风险。所谓 fork bomb 是指数增长耗尽系统资源的反面例子；理解增长规律即可，不要在日常电脑上尝试。

## 4. `execve()`：让当前进程运行另一份程序

`fork` 得到的是当前进程的副本；如果想运行一个**不同的程序**，需要 `execve(path, argv, envp)`。

- `path`：要运行的可执行文件路径；
- `argv`：给新程序的命令行参数；
- `envp`：给新程序的环境变量，如 `PATH`。

`execve` 把**当前进程的程序映像**替换为新程序：新代码和数据被加载，执行位置来到新程序入口。它不会额外创建一个进程；成功后不会返回原来的调用位置，只有失败才返回错误。

进程的一些 OS 管理状态会保留，例如 PID、当前工作目录；打开的文件描述符通常也会保留，但标记了 close-on-exec 的会被关闭。因而可以先设置好工作目录、输入输出等，再让新程序在这个环境里启动。

> `execve` 与 `fork` 的区别：`fork` 增加一个进程；`execve` 把现有进程“换成”另一个程序。二者可以组合，但谁也不等于谁。

### `PATH` 从哪里发挥作用？

`execve` 接收的是具体路径，本身不搜索 `PATH`。Shell 或 `execvp` 等库函数会根据 `PATH` 依次寻找可执行文件，然后调用 `execve`。这解释了为什么改动 `PATH` 可能让原本能运行的命令变成“找不到”。

## 5. `fork + execve + wait`：Shell 如何启动命令

在 UNIX 上，启动一个新程序常见的过程是：

```text
Shell（父进程）
   ├─ fork() → 创建子进程
   ├─ 子进程：设置输入/输出 → execve() → 运行目标程序
   └─ 父进程：waitpid() 等待子进程并获取结果
```

这里的 `waitpid()` 不是“启动程序”的一部分，而是父进程**等待并回收指定子进程的退出结果**。如果 Shell 不需要同步等待，也可以继续做别的事，稍后再回收。

一个常见误解是：`execve()` 之后“子进程变成孙进程”。实际并没有新增进程；子进程 PID 仍是原来的 PID，只是运行的程序换了。

## 6. `exit`：运行结束后还剩什么？

进程完成工作后会退出，并向父进程留下退出状态。父进程可通过 `wait`/`waitpid` 获取状态、回收相关记录。

- `_exit(status)`：直接请求结束当前进程；
- C 库的 `exit(status)`：先处理标准 I/O 缓冲、退出处理函数等，再结束进程；
- Linux 在线程层面还有 `exit` 与 `exit_group` 的区别，当前先不必展开。

进程刚退出而父进程尚未回收其状态时，系统仍保留一小部分退出信息，这就是后面会遇到的“僵尸进程”。它不是还在执行代码。

## 7. 为什么同一段 `fork` 代码，输出还可能让人困惑？

这节课有两层原因值得分开看：

1. **调度顺序不确定**：父、子进程谁先运行由 OS 决定，所以多次运行时，输出的先后顺序可能变化。
2. **`printf` 有用户态缓冲区**：`fork` 会复制进程内存，连尚未真正写出的缓冲内容也可能被复制；接到终端或管道时，缓冲策略又可能不同。因此“调用了几次 `printf`”不一定等于“底层发生了几次 `write`”。

研究这类现象时，先区分 `printf`（C 库函数）和 `write`（向 OS 请求输出的接口），再比较不同运行方式下的实际 `write` 调用。第二讲的 `strace` 正好能用来观察；`setbuf`、`fflush` 等可以控制缓冲行为。不要只凭一次屏幕输出推断所有执行顺序。

**暂不做**

如果你现在没有 Linux 环境，先完成概念和纸上追踪即可。macOS 也有 `fork`/`exec`/`wait`，但 `/proc` 和 `strace` 不是它的通用接口；后续实验用 Linux 环境会更贴近讲义。

## 9. 40 秒脱稿复述

程序是磁盘上的静态描述，进程是它运行起来后的状态机实例。OS 保存每个进程的内存、寄存器和管理信息，让它们仿佛各自拥有一台计算机。`fork` 复制当前进程，父子从同一位置继续，但返回值不同；`execve` 不创建进程，而是把当前进程替换成另一份程序。Shell 通常先 `fork`，让子进程 `execve` 目标程序，父进程再用 `waitpid` 等待退出状态。进程退出后，父进程还要回收它的结果。

## 10. 自测题

先合上下面的答案，尽量脱稿回答。答不出时只补对应的小节。

1. 同一个可执行文件启动两次，为什么会有两个进程？
2. `fork()` 成功后，有几个进程会从调用后的语句继续？它们怎样区分自己是父还是子？
3. 一个普通变量在 `fork` 后由子进程修改，父进程会直接看到改变吗？
4. `execve()` 会新建一个进程吗？成功后还会回到原调用点吗？
5. Shell 启动命令时，`fork`、`execve`、`waitpid` 分别负责什么？
6. 为什么 `printf` 的次数不一定等于实际 `write` 的次数？
7. 进程退出后，父进程为什么还要 `wait`？

### 参考答案

1. 可执行文件只是创建初始状态的静态描述；OS 可以多次加载同一文件，建立各自的运行状态和 PID，因此得到不同进程。
2. 两个。父进程收到子进程 PID，子进程收到 `0`；如果失败则只有原进程，返回 `-1`。
3. 对普通内存变量不会。父子有各自的内存视图；要共享变化需要明确使用进程间通信或共享内存机制。注意打开的文件等 OS 资源另有继承与共享规则。
4. 不会。它替换当前进程运行的程序，通常保留 PID；成功后从新程序入口执行，不再回到旧程序的 `execve` 下一行。
5. `fork` 创建子进程；子进程通过 `execve` 加载目标程序；父进程用 `waitpid` 等待并回收退出状态。
6. `printf` 先写入 C 库缓冲区，缓冲内容可在 `fork` 时被复制，随后由父子分别刷新；直接写终端与接入管道的缓冲策略也不同。`write` 才是观察实际系统调用的关键。
7. 子进程退出后 OS 需要暂存退出状态供父进程读取；父进程 `wait` 后取得结果并完成回收，否则可能暂时留下僵尸进程记录。
