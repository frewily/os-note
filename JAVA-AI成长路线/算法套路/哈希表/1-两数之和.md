# 1. 两数之和

---

## 题目

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出**和为目标值** `target` 的那**两个**整数，并返回它们的数组下标。每种输入只会对应一个答案，且不能使用两次相同的元素。

```
输入：nums = [2,7,11,15], target = 9
输出：[0,1]

输入：nums = [3,2,4], target = 6
输出：[1,2]
```

---

## 你的关键思路

> 二刷感悟：时隔几个月刷完 hot100，现在重新刷第一题，亲切的不得了，以为已经可以秒了。这不就是三数只和的低配版嘛，二分，双指针，随便解！等搓完代码才发现数组是无序的。行呗，加一个哈希表建立映射关系后再对对数组排序，排完序后又发现数组中的元素有重复的，之前建立的映射关系会被重复覆盖掉，走不通......苦思冥想半小时，依旧想不出来O(n)的解法，最后又跑去看题解，不得不感叹这思路是真的妙啊！感觉给我一天也想不出这种解法。路漫漫其修远兮，加油吧

> **复盘补充（为什么"边查边存"是正解）**：
> 1. 排序+双指针走不通：排序破坏下标，而这题要返回**下标**
> 2. 先建完整 map 再查有坑：重复元素会覆盖 map 里的下标
> 3. 正解关键：`target - nums[i]` 若存在，必在 i 的左边或右边——**边遍历边查，查不到就存**，遍历到右边配对元素时，左边的早已在 map 里
> 4. "先查后存"天然避免自己配自己（同一个元素用两次），也不会漏
> 5. 三数之和 = 这题 + 排序去重；这题是"查"的思维，三数之和是"指针收缩"的思维——不完全一样

## 你的代码

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        if(nums.length == 2) return new int[]{0,1};
        Map<Integer, Integer> map = new HashMap<>();
        for(int i = 0; i < nums.length; i++){
            if(map.containsKey(target - nums[i])){
                return new int[]{i, map.get(target - nums[i])};
            }
            map.put(nums[i], i);
        }
        return new int[]{};
    }
}
```

---

## 复杂度

- 时间：O(n)，单遍遍历
- 空间：O(n)，HashMap
