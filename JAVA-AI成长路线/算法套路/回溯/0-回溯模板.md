# 回溯模板

---

## 核心

回溯本质是**穷举 + 剪枝**——做选择 → 递归 → 撤销选择。适合排列、子集、组合类问题。

---

## 通用模板

```java
void backtrack(路径, 选择列表) {
    if (满足结束条件) {
        加入结果集;
        return;
    }
    
    for (选择 : 选择列表) {
        做选择（路径.add）;
        backtrack(路径, 选择列表);
        撤销选择（路径.remove）;
    }
}
```

---

## 全排列 vs 子集

**全排列**：`[1,2,3]` → `[1,2,3], [1,3,2], [2,1,3]...`（顺序重要，需要 used 数组标记已选）

**子集**：`[1,2,3]` → `[], [1], [2], [3], [1,2]...`（顺序不重要，用 startIndex 控制不走回头路）

| | 全排列 | 子集 |
|--|--------|------|
| 重复选择 | ❌ 不能重复选 | ❌ 不能重复选 |
| 顺序是否重要 | ✅ 重要 `[1,2]` ≠ `[2,1]` | ❌ 不重要 |
| 去重用 | `used[]` 标记已用的元素 | `startIndex` 控制从哪开始选 |
| 结束条件 | path.size() == nums.length | 每次进入都加入结果集 |
| 结果数 | n! | 2ⁿ |

## 变体辨析：当回溯不再"标准"

上面全排列和子集是标准的回溯模板——for 循环遍历输入数组。但有些题的"选择来源"不是数组，需要跳出模板的惯性思维。

### 变体一：选择来源于状态，不是数组

**典型题**：[[22-括号生成]]

```java
// 标准模板：for 循环遍历选择列表
for (int num : nums) { ... }

// 括号生成：没有输入数组，用 if 代替 for
if (left < n)  { 加 '('; backtrack(... left+1, right); 撤销; }
if (right < left) { 加 ')'; backtrack(... left, right+1); 撤销; }
```

**关键区别**：不是"从一堆东西里选一个"，而是"根据当前状态判断能不能加某种符号"。

### 变体二：选择来源于棋盘/图

**典型题**：[[79-单词搜索]]

```java
// 不是 for 循环遍历选择列表
// 而是 4 个固定的方向，用坐标控制
boolean res = dfs(board, r+1, c) || dfs(board, r-1, c)
            || dfs(board, r, c+1) || dfs(board, r, c-1);
```

**关键区别**：回溯发生在"移动"上，而不是"挑选"上。visited 标记走没走过，相当于全排列的 used[] 数组。

### 三张表对比全部 6 题

| | 选择来源 | 去重方式 | 返回什么 |
|--|---------|---------|---------|
| **全排列** | for 遍历数组 | `used[]` | 收集全部结果 |
| **子集** | for 遍历数组，从 start 开始 | `startIndex` | 每个节点都收集 |
| **组合总和** | for 遍历数组，从 start 开始 | `i`（可重复） | 收集全部结果 |
| **电话号码** | for 遍历映射字符串 | `index` 指向 digits | 收集全部结果 |
| **括号生成** | if 判断状态 | `left`/`right` 控制 | 收集全部结果 |
| **单词搜索** | 四方向坐标移动 | `board[r][c]='\0'` 标记 | 找到就提前返回 true |

### 举一反三的核心

识别一道题是不是回溯，不看它有没有 for 循环，而是看它是不是：

```
做选择 → 递归 → 撤销选择  的三角结构
```

只要满足这个结构，不管选择来自数组、状态还是棋盘，都能套回溯的思路。
