# 常用命令速查

---

## 容器生命周期

```bash
docker run <镜像>          # 创建并启动容器
docker start <容器>        # 启动已停止的容器
docker stop <容器>         # 停止容器
docker restart <容器>      # 重启容器
docker rm <容器>           # 删除容器
docker rm -f <容器>        # 强制删除运行中的容器
```

---

## 查看信息

```bash
docker ps                  # 运行中的容器
docker ps -a               # 所有容器（含已停止）
docker images              # 本地镜像列表
docker logs <容器>         # 查看日志
docker logs -f <容器>      # 实时跟踪日志
docker stats               # 容器资源占用（CPU/内存）
docker inspect <容器>      # 查看容器详细信息
```

---

## 进入容器

```bash
docker exec -it <容器> bash     # 进入容器内部
docker exec -it <容器> sh       # 如果 bash 不可用
```

---

## 镜像操作

```bash
docker pull <镜像>          # 拉取镜像
docker build -t <名称> .    # 构建镜像
docker rmi <镜像>           # 删除镜像
docker tag <镜像> <新标签>   # 打标签
docker push <镜像>          # 推送到仓库
```

---

## 网络和存储

```bash
docker network ls           # 查看网络
docker volume ls            # 查看数据卷
```

---

## Compose

```bash
docker compose up -d        # 启动所有服务
docker compose down         # 停止并删除
docker compose logs -f      # 查看日志
docker compose ps           # 查看状态
docker compose exec <服务> bash   # 进入容器
docker compose up -d --build     # 重新构建后启动
```

---

## 清理

```bash
docker system prune         # 清理未使用的容器、网络、镜像
docker system prune -a      # 更彻底的清理（含未使用的镜像）
docker system prune -a --volumes  # 连数据卷一起清
```

> **`docker compose down -v` vs `docker system prune` 对比**

| | `docker compose down -v` | `docker system prune` |
|---|---|---|
| **作用范围** | 仅当前 compose 项目 | **整个 Docker**，全局扫垃圾 |
| **行为** | 停 + 删容器、网络、**数据卷** | 删所有**未被使用**的容器、网络、dangling 镜像 |
| **目标** | 消灭某个项目（含数据） | 腾出磁盘空间 |
| **危险性** | 只影响当前项目 | 默认不带 `--volumes` 不删数据卷，较安全 |
| **常用场景** | 开发完一个项目 / 想重置数据库 | 磁盘快满了 / 残留容器太多 |

- `docker compose down -v` = **"这个项目我不要了，连数据库一起删干净"**
- `docker system prune -a` = **"Docker 硬盘满了，扫一遍垃圾"**
- `docker system prune -a --volumes` 最暴力——**全局所有未使用的资源全清**，慎用
