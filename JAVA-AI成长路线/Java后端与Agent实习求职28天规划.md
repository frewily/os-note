# Java 后端与 Agent 实习求职 28 天规划

## 1 规划目标

本计划用于在 28 天内完成第一轮实习投递准备。目标岗位以 Java 后端实习为主，同时投递 Agent 应用开发、AI 应用后端和 RAG 工程相关岗位。

28 天后的目标不是掌握所有知识，而是形成一套可以投递、可以演示、可以解释、可以继续迭代的求职材料与能力体系。

核心策略：

- 以 Java 后端能力作为求职基本盘。
- 以 Java 和 Python 混合架构的 Agent 项目作为差异化项目。
- 将黑马点评作为 Redis、高并发和缓存知识的辅助项目。
- 算法侧重高频题型与独立完成能力，不追求题量。
- 第 28 天开始投递，此后保持投递、复盘和学习并行。

## 5 算法执行规则

每天刷 3 道题可以执行，但建议采用“2 道新题加 1 道复习题”，而不是每天学习 3 道全新的题。

### 5.1 单题流程

1. 独立思考 20 至 30 分钟。
2. 能写出思路但无法编码时，先写伪代码，再查看局部提示。
3. 完全没有思路时阅读题解，记录自己缺少的是题型识别、数据结构知识还是实现细节。
4. 关闭题解后独立重写，不复制答案。
5. 在次日、7 天后分别重做一次。

### 5.2 题目记录

每道重点题只记录以下内容：

- 题型和核心方法。
- 为什么想到这种方法。
- 容易写错的边界条件。
- 时间复杂度和空间复杂度。
- 下次看到什么特征时应联想到这道题。

### 5.3 完成标准

- 简单题在 15 至 20 分钟内独立完成。
- 常见中等题在 30 至 40 分钟内写出主要思路和代码。
- 能解释解法、复杂度和边界条件。
- 一道题连续两次独立完成后，才视为基本掌握。

## 6 八股学习方案

八股学习采用“理解原理、联系项目、脱稿表达、间隔复习”的循环。每天八股时间约 2 小时，其中 70 分钟学习新内容，30 分钟结合项目复述，20 分钟复习前一天内容。

### 6.1 优先级

第一优先级是必须熟练掌握的内容：

- Java 基础与集合：`equals`、`hashCode`、String、泛型、反射、HashMap、ConcurrentHashMap。
- 并发编程：线程池、synchronized、volatile、CAS、AQS、ReentrantLock、ThreadLocal、死锁。
- JVM：内存区域、对象创建、类加载、双亲委派、垃圾回收、OOM 排查。
- Spring：IOC、Bean 生命周期、AOP、动态代理、事务、MVC、拦截器和自动配置。
- MySQL：索引、B+ 树、联合索引、覆盖索引、事务、MVCC、锁和慢查询。
- Redis：数据结构、缓存问题、持久化、淘汰、Lua、分布式锁、Stream 和 GEO。
- MyBatis：`#{}` 与 `${}`、动态 SQL、缓存、分页和 N+1 查询。

第二优先级是结合 Agent 岗位准备的内容：

- HTTP、HTTPS、TCP、Cookie、Session、JWT 和跨域。
- SSE、WebSocket、同步异步、阻塞非阻塞、Mono、Flux 和 WebClient。
- RAG 的 Embedding、分块、召回、Top K、重排序和生成。
- Agent 的 Prompt、Tool、AgentExecutor、对话历史、幻觉和费用控制。
- Linux、Docker、Docker Compose、Nginx 和基础故障排查。

第三优先级只需了解概念：Redis Cluster、Kafka 深入原理、Netty 源码、Spring Cloud 全家桶、分布式事务源码、JVM 深度调优和大模型训练微调。

### 6.2 单个知识点的掌握标准

每个知识点至少回答以下问题：

1. 它是什么。
2. 它解决什么问题。
3. 常见方案有什么区别。
4. 它在自己的项目中如何使用。
5. 如果不这样做，可能出现什么问题。

完成标准：30 秒能说出结论，2 分钟能解释原理，能联系项目举例，能指出一个常见坑，并能说出一个替代方案。笔记以问题和答案为主，避免抄写大段教程。

## 11 项目掌握标准

AI 辅助编写代码本身不是问题，判断标准是能否对最终代码负责。

项目来自课程或开源仓库时，需要准确说明来源、已有能力和本人改造，不能将项目整体描述为从零独立开发。

一个核心模块达到以下要求，才视为真正掌握：

- 能说明它解决的业务问题。
- 能画出输入、处理和输出的数据流。
- 能解释关键技术的选择理由和替代方案。
- 能指出至少一个缺陷和改进方向。
- 能独立排查常见异常。
- 不依赖 AI，能够重写关键方法或伪代码。
- 能通过 Git 提交和代码位置说明本人新增或修改的部分。

投递前需要独立掌握的核心代码：

- Agent 项目中的聊天请求完整链路。
- Java WebClient 与 Python SSE 通信。
- 会话持久化与 Redis 缓存。
- JWT 生成、解析和鉴权流程。
- 文档分块、Embedding、召回、重排序与生成。
- 面试官模式的创建、提问、追问、结束和报告链路。
- 黑马点评中的缓存逻辑。
- Lua 秒杀资格判断、Redis Stream 消费和数据库落单。

## 12 简历策略

### 12.1 中文简历

中文简历是第一优先级，控制在一页。项目描述只保留能够证明能力、并能接受追问的内容。

Agent 项目可以描述为基于课程与开源项目的二次开发，但只有本人真正完成并掌握的面试官模式、关键修复和工程化改造才能写作个人成果。不得使用“从零搭建”“独立完成整套系统”等不符合事实的表述。

推荐项目顺序：

1. SpringBoot RAG Agent 智能问答系统。
2. 黑马点评。

### 12.2 英文简历

当前无需优先制作英文简历。国内中小厂和多数中厂主要使用中文简历。中文简历定稿后，可以用半天制作一份英文版本备用，用于外企、国际团队或要求英文材料的岗位。

英文简历不会显著弥补项目与基础能力的不足，因此它的优先级低于项目整改、中文简历和面试准备。

## 16 执行调整规则

- 一天任务未完成时，最多顺延其中最重要的一项，不将所有欠账堆到第二天。
- 连续两天完成率低于 70% 时，减少新知识数量，优先完成项目主线。
- 项目出现严重问题时，可以临时增加项目时间，但算法每天至少保留 1 道复习题。
- 每周第 7 天不安排大量新内容，用于补漏、复习和模拟面试。
- 课程或考试临时增加时，保留每日最低任务：1 小时项目、1 小时八股、1 道算法题。
- 开始投递后，根据真实面试问题动态调整学习优先级。
