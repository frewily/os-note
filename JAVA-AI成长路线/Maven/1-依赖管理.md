# 依赖管理

---

## 核心

Maven 用 **GAV 坐标**唯一定位一个 jar 包，你只需要声明"我要什么"，Maven 自动从仓库下载并管理版本。

---

## GAV 坐标

每个依赖用三个信息唯一确定：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>     <!-- 组织/公司 -->
    <artifactId>spring-boot-starter-web</artifactId> <!-- 项目名 -->
    <version>3.2.0</version>                         <!-- 版本号 -->
</dependency>
```

**从哪找 GAV**：
- [mvnrepository.com](https://mvnrepository.com) — 搜任何依赖
- 复制 XML 直接贴到 pom.xml

**vibe coding 视角**：AI 生成 pom.xml 时经常写错版本号或在 mvnrepository 上找不到的依赖，加依赖后最好去 mvnrepository 确认一下。

---

## scope——依赖的作用范围

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <scope>compile</scope>   <!-- 默认值，不写就是这个 -->
</dependency>
```

| scope | 编译 | 运行 | 打包 | 典型场景 |
|-------|------|------|------|---------|
| **compile**（默认） | ✅ | ✅ | ✅ | 大部分依赖（Spring、MyBatis） |
| **provided** | ✅ | ❌ | ❌ | Servlet API、Lombok（容器已提供） |
| **runtime** | ❌ | ✅ | ✅ | MySQL 驱动（编译用接口，运行才加载实现） |
| **test** | ❌ | ❌ | ❌ | JUnit、Mockito（只在测试代码中用） |

```xml
<!-- 实际例子 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <scope>compile</scope>         <!-- 默认，编译和运行都需要 -->
</dependency>

<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <scope>provided</scope>        <!-- 编译时需要，运行时 IDEA 已处理 -->
</dependency>

<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>         <!-- 编译时用 JDBC 接口，运行时才需要驱动 -->
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>            <!-- 只在测试代码中 -->
</dependency>
```

## 传递依赖

```xml
<!-- 你只声明了这一个 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<!-- 但实际上它把依赖的依赖都带进来了 -->
spring-boot-starter-web
    ├── spring-boot-starter
    │   ├── spring-boot
    │   ├── spring-boot-autoconfigure
    │   └── spring-boot-starter-logging
    ├── spring-boot-starter-json
    │   ├── jackson-databind
    │   └── jackson-datatype-jdk8
    ├── spring-boot-starter-tomcat
    │   ├── tomcat-embed-core
    │   └── tomcat-embed-el
    └── spring-webmvc
        └── spring-web
```

**好处**：引入一个 starter，自动拉齐所有兼容的版本。
**坏处**：可能引入你不需要的依赖，或者两个依赖引入了同一个 jar 的不同版本 → 冲突。

---

## 排除不需要的传递依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-tomcat</artifactId>
            <!-- 排除 Tomcat，改用 Undertow -->
        </exclusion>
    </exclusions>
</dependency>

<!-- 然后引入替代 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-undertow</artifactId>
</dependency>
```

**什么时候需要排除**：
- 项目用 Undertow 不用 Tomcat
- 依赖 A 引入了 jackson 2.12，依赖 B 引入了 jackson 2.14 → 排除低版本
- 不需要某个传递依赖（如某些日志实现）

## dependencyManagement——统一管理版本

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.google.guava</groupId>
            <artifactId>guava</artifactId>
            <version>32.1.3-jre</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```

**作用**：在父 pom 中声明版本号，子模块引用时不需要写 version。
**它和 dependencies 的区别**：

| | dependencies | dependencyManagement |
|--|-------------|-------------------|
| 是否引入 jar | ✅ 直接引入 | ❌ 只声明版本 |
| 子模块是否继承 | ✅ 全部引入 | ✅ 继承版本号，按需声明 |

Spring Boot 的 `spring-boot-dependencies` 就是用 `dependencyManagement` 统一管理了所有依赖版本——所以你引入 spring-boot-starter-xxx 时不需要写 version。

## 依赖冲突规则

**当同一个 jar 出现不同版本时，Maven 按以下规则选一个：**

```
① 最短路径优先
   项目直接依赖 A → guava:30.0
   项目传递依赖 B → C → guava:28.0
   结果：选 guava:30.0（路径更短）

② 同路径长度，最先声明优先
   项目直接依赖 A → guava:30.0（第 1 个写的）
   项目直接依赖 B → guava:28.0（第 2 个写的）
   结果：选 guava:30.0（先声明）
```

**实际用法**：出现奇怪报错（如 `NoSuchMethodError`、`ClassNotFoundException`），大概率是依赖冲突，用 `mvn dependency:tree` 查看。

## mvn dependency:tree——排查依赖

```bash
# 查看所有传递依赖树
mvn dependency:tree

# 过滤指定依赖
mvn dependency:tree -Dincludes=com.google.guava

# 输出到文件
mvn dependency:tree > deps.txt
```

输出示例：

```
[INFO] com.example:ai-chat:jar:1.0.0
[INFO] +- org.springframework.boot:spring-boot-starter-web:jar:3.2.0:compile
[INFO] |  +- org.springframework.boot:spring-boot-starter:jar:3.2.0:compile
[INFO] |  |  +- org.springframework.boot:spring-boot:jar:3.2.0:compile
[INFO] |  |  \- org.springframework.boot:spring-boot-starter-logging:jar:3.2.0:compile
```

## 项目关联

| 场景 | 说明 |
|------|------|
| **加一个新依赖** | mvnrepository 找 GAV → 贴到 pom.xml → mvn dependency:tree 检查冲突 |
| **升级版本** | 改 version 或改 properties 中的版本变量 → 测试是否兼容 |
| **class 找不到 / 方法找不到** | `mvn dependency:tree` 查冲突 → 排除低版本 |
| **排除不需要的依赖** | 用 `<exclusions>` 排除传递进来的无用 jar |
