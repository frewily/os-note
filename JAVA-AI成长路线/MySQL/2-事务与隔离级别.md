# 事务与隔离级别

---

## 核心

事务是一组操作要么全部成功、要么全部回滚。隔离级别决定并发事务之间的可见性。

---

## 事务四大特性（ACID）

| 特性 | 含义 | 实现 |
|------|------|------|
| **原子性（A）** | 事务内的操作全部成功或全部回滚 | undo log |
| **一致性（C）** | 事务前后数据状态一致（业务层面的约束） | AID 共同保证 |
| **隔离性（I）** | 并发事务互不干扰 | 锁 + MVCC |
| **持久性（D）** | 提交后数据永久保存 | redo log |

实际项目中**一致性是目标，原子性、隔离性、持久性是手段**。换句话说：ACID 的 AID 都是为了最终保证 C。

---

## 三种并发问题

```sql
-- 准备数据
INSERT INTO accounts (id, balance) VALUES (1, 1000);
```

### 脏读——读到未提交的数据

```
事务 A：UPDATE balance = 800 WHERE id = 1     (未提交)
事务 B：SELECT balance → 800                   (读到了未提交的数据)
事务 A：ROLLBACK                                (回滚了)
→ 事务 B 读到的 800 是脏数据，实际上余额还是 1000
```

### 不可重复读——同一次事务内两次读同一行结果不同

```
事务 A：SELECT balance → 1000
                  事务 B：UPDATE balance = 800 WHERE id = 1; COMMIT
事务 A：SELECT balance → 800                    (同一行，两次读不一样)
```

### 幻读——同一次事务内两次范围查询行数不同

```
事务 A：SELECT * FROM accounts WHERE balance > 500 → 3 行
                  事务 B：INSERT INTO accounts (balance=600); COMMIT
事务 A：SELECT * FROM accounts WHERE balance > 500 → 4 行  (多了一行"幻影"数据)
```

---

## 四种隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| **读未提交** | ❌ 可能 | ❌ 可能 | ❌ 可能 |
| **读已提交（RC）** | ✅ 解决 | ❌ 可能 | ❌ 可能 |
| **可重复读（RR）** | ✅ 解决 | ✅ 解决 | ⚠️ InnoDB 通过间隙锁解决 |
| **串行化** | ✅ 解决 | ✅ 解决 | ✅ 解决 |

**MySQL InnoDB 默认是 RR（可重复读）**。

**vibe coding 视角**：
- 大部分项目用**默认的 RR 就行**，不用特地改成 RC
- `@Transactional` 注解默认就是 RR 级别（Spring 遵从数据库默认）
- 使用 `@Transactional(isolation = Isolation.READ_UNCOMMITTED)` 时，确认业务是否真的能接受脏读

## @Transactional 的使用

```java
@Service
public class OrderService {
    
    @Autowired
    private OrderMapper orderMapper;
    
    @Autowired
    private AccountMapper accountMapper;
    
    @Transactional(rollbackFor = Exception.class)
    public void createOrder(OrderDTO dto) {
        orderMapper.insert(dto.toOrder());          // 插入订单
        accountMapper.deduct(dto.getUserId(),        // 扣余额
            dto.getAmount());
        // 这两步要么都成功，要么都回滚
    }
}
```

**`@Transactional` 失效的常见原因**：

1. 同一个类中方法直接调用（A 方法调用 B 方法，B 有 @Transactional → 不生效，因为没走代理）
2. `rollbackFor` 默认只回滚 `RuntimeException`，受检异常不会回滚
3. `private` 方法上的 `@Transactional` 不生效

## 项目关联

| 场景 | 说明 |
|------|------|
| **创建订单扣库存** | 订单插入 + 库存扣减必须在同一事务，否则可能超卖 |
| **AI 客服消息存储** | 消息入库 + Token 消耗记录，要么一起成功要么一起回滚 |
| **用户注册** | 用户表插入 + 初始角色分配，用事务保证一致性 |
