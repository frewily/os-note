# 进阶用法与坑

---

## 批量插入

```java
// ❌ 逐条插入（循环调用 insert）——性能极差
for (User user : userList) {
    userMapper.insert(user);  // 每条一次数据库 IO
}

// ✅ 批量插入——一条 SQL 插入多条
void insertBatch(@Param("list") List<User> list);

// XML 实现
<insert id="insertBatch">
    INSERT INTO users(name, email) VALUES
    <foreach collection="list" item="item" separator=",">
        (#{item.name}, #{item.email})
    </foreach>
</insert>
```

MP 提供了 `saveBatch` 方法：

```java
// 如果 Service 层继承了 IService
userServiceImpl.saveBatch(userList);
// 内部也是逐条 insert，但包装在同一个事务中，效率比单独循环高
```

## 逻辑删除

```java
// 实体类上标记逻辑删除字段
public class User {
    private Long id;
    private String name;
    
    @TableLogic
    private Integer deleted;  // 0-未删，1-已删
}

// 配置后：
// userMapper.deleteById(1) 
// → 实际执行：UPDATE users SET deleted=1 WHERE id=1
// userMapper.selectList(null)
// → 自动追加：WHERE deleted=0
```

**vibe coding 视角**：项目使用逻辑删除时，AI 可能不知道你的删除规则，生成的 `DELETE` 语句会变成物理删除。确保在 prompt 中说明。

## 自动填充

```java
public class User {
    
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;
    
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

```java
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {
    
    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", 
            LocalDateTime.class, LocalDateTime.now());
        this.strictUpdateFill(metaObject, "updateTime", 
            LocalDateTime.class, LocalDateTime.now());
    }
    
    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", 
            LocalDateTime.class, LocalDateTime.now());
    }
}
```

效果：插入时 `createTime` 和 `updateTime` 自动赋值，更新时 `updateTime` 自动更新——不需要手动 set。

## 乐观锁

```java
// 实体类
public class Product {
    private Long id;
    private String name;
    private Integer stock;
    
    @Version
    private Integer version;  // 乐观锁版本号
}
```

```java
// 配置乐观锁插件
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
    interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
    return interceptor;
}
```

**原理**：

```
线程 A：查询 stock=10, version=1
线程 B：查询 stock=10, version=1

线程 A：UPDATE SET stock=9, version=2 WHERE id=? AND version=1 → 成功
线程 B：UPDATE SET stock=9, version=2 WHERE id=? AND version=1 → 失败
       （因为 version 已被 A 改成 2 了）

→ 线程 B 的更新影响行数为 0，抛出异常或重试
```

**适用场景**：库存扣减、余额更新等需要防止并发覆盖的场景。

## 常见坑

### 字段为空时 MyBatis 不更新

```java
User user = new User();
user.setId(1L);
user.setName("新名字");    // email 没设置，为 null
userMapper.updateById(user);
// → UPDATE users SET name='新名字' WHERE id=1
// email 不会被更新为 null（MyBatis 默认忽略 null 字段）
```

如果需要把字段更新为 null，加 `@TableField(strategy = FieldStrategy.IGNORED)`。

### Wrapper 条件顺序

```java
wrapper.eq("status", 1)
       .eq("status", 2);   // 后面的 eq 会覆盖前面的
// 实际条件：WHERE status = 2

// 需要用 OR
wrapper.eq("status", 1)
       .or()
       .eq("status", 2);
// 实际条件：WHERE status = 1 OR status = 2
```

## 项目关联

| 场景 | 说明 |
|------|------|
| **批量消息入库** | AI 客服的对话记录批量写入用 `saveBatch` |
| **逻辑删除** | 用户注销标记 `deleted=1`，数据保留可恢复 |
| **自动填充** | 所有表的 `create_time` / `update_time` 统一自动填充 |
| **乐观锁** | 扣减 Token 余额时防止并发超扣 |
