### 今天学习到的知识

- HTTP 是应用层协议，负责规定请求和响应的内容格式。
- TCP 负责可靠、有序地传输字节流，并使用端口号区分具体应用。
- IP 负责标识主机，并让数据包跨网络找到目标主机。
- 以太网负责局部网络中的数据帧传输，使用 MAC 地址识别网卡。
- 访问外网时，IP 头中的目标地址仍是远程服务器 IP，但当前以太网帧的目标 MAC 通常是默认网关的 MAC。
- TCP 首部会携带源端口、目标端口、序列号、确认号和控制标志等信息；IP 层再添加源 IP 和目标 IP；链路层再添加 MAC 地址。
- 数据封装关系：HTTP 数据 → TCP 段 → IP 包 → 以太网帧。
- `200` 表示请求成功，`301` 表示永久重定向，`404` 表示资源不存在，`500` 表示服务器内部处理错误。
- 收到 `404` 说明某个 HTTP 服务已经返回了响应，通常表示 TCP 连接已经建立；TCP 失败时一般收不到 HTTP 状态码。

## 2026-09-26（🟡 理解但不流畅）

- TIME-WAIT 与 2MSL

### 今天学习到的知识

- TCP 序列号标记字节流中一段数据的起始位置；接收方可据此排序、重组并发现缺失数据。
- ACK 通常表示接收方下一个期待的字节序号，是累计确认；它确认连续收到的数据，不是最新到达的乱序段。
- 若 `seq=1000` 的数据长 500 字节，下一个期望位置是 1500；若 `seq=2000` 的段先到而中间有缺口，ACK 仍为 1500；缺口补齐且连续收到至 2499 后，ACK 前进到 2500。
- `ACK=1` 是 ACK 标志位，表示确认号字段有效；`ack=2500` 才是具体的确认号。
- 校验和发现报文损坏时，接收方通常丢弃该段；发送方未收到确认后会通过超时重传恢复数据。重复 ACK 也可能触发快速重传。
- 滑动窗口允许多个未确认的数据段同时在途，减少逐段等待 ACK 的空闲时间；接收窗口 `rwnd` 反映接收方可接收空间。
- 流量控制保护接收方，拥塞控制根据路径状况调整发送量；`cwnd` 由发送方维护，用于估计网络可承受的在途数据量，不是路由器直接通告的窗口。
- TIME-WAIT 等待 2MSL：让对端在最后 ACK 丢失时仍可重发 FIN 并得到再次确认；同时给旧连接的延迟报文留出过期时间，降低其干扰后续复用相同四元组连接的风险。
