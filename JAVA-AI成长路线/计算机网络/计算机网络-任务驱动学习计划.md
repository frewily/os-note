## 二、八个任务模块

### 模块一：网络是透明的吗？—— 第一次抓包

> ⏱ 约 3~4 天 · 理论 40% + 实践 60%

**任务**  
用 Wireshark 抓取访问自己项目 API 的全过程，识别出 HTTP 请求/响应报文结构。

**学习目标**
- 什么是协议、报文、封装
- HTTP 请求行 / 响应行 / Header / Body
- 常见状态码（200 / 301 / 403 / 404 / 500）
- 客户端-服务器模型

**交付笔记**  
[[第一次抓包：我看到了网络请求的样子]]
- 附 Wireshark 截图，标注每个字段含义
- 用自己的话解释"一次 HTTP 请求经历了什么"

---

### 模块二：浏览器怎么找到服务器？—— DNS 解析

> ⏱ 约 3~4 天 · 理论 50% + 实践 50%

**任务**  
用 `dig` 命令解析 `google.com` 和你的项目域名，画出 DNS 解析链路图。

**学习目标**
- 域名层级结构（根域名 → TLD → 权威域名服务器）
- DNS 递归查询 vs 迭代查询
- DNS 缓存机制（浏览器缓存 → OS 缓存 → 本地 DNS 缓存）
- 与后端相关的：CDN 原理、DNS 负载均衡

**与后端的连接**  
配置 Nginx 或云服务器时，DNS 如何把你的域名指向服务器 IP。

**交付笔记**  
[[DNS解析：从域名到IP发生了什么]]
- 附 dig 命令输出和解析链路图

---

### 模块三：TCP 三次握手 —— 用 Java Socket 亲手建立连接 ⭐

> ⏱ 约 4~5 天 · 理论 40% + 实践 60%

**任务**
1. 写一个 **Java Socket** 服务端 + 客户端（不用框架，纯 Java）
2. 用 Wireshark 抓包，找到三次握手的三个报文（SYN → SYN-ACK → ACK）
3. 观察 SEQ 和 ACK 号如何变化

**学习目标**
- TCP 报文段结构（Source Port、Dest Port、SEQ、ACK、Flags）
- 三次握手状态变迁（CLOSED → SYN-SENT → ESTABLISHED）
- 端口号的作用
- 为什么是三次而不是两次或四次？

**交付笔记**  
[[TCP三次握手：我用Java亲手建立了一条连接]]
- 附 Java 核心代码 + Wireshark 报文截图
- 用流程图画出三次握手

---

### 模块四：TCP 四次挥手与可靠传输 ⭐

> ⏱ 约 5~6 天 · 理论 50% + 实践 50%

**任务**
1. 扩展 Java Socket 程序，客户端主动关闭连接
2. Wireshark 抓包观察四次挥手（FIN → ACK → FIN → ACK）
3. 观察 TIME_WAIT 状态

**学习目标**
- 四次挥手流程与状态变迁
- 为什么是四次不是三次？（半关闭状态）
- TIME_WAIT 为什么需要 2MSL？
- TCP 可靠传输机制：校验和、序列号、确认应答、超时重传
- 流量控制：滑动窗口协议

**交付笔记**  
[[TCP四次挥手与可靠传输]]
- 回答核心问题：为什么 TIME_WAIT 要等 2MSL？

---

### 模块五：TCP 拥塞控制 —— 网络塞车了怎么办？

> ⏱ 约 4~5 天 · 理论 60% + 实践 40%

**任务**  
用 Wireshark 分析一个下载过程的窗口变化，观察拥塞控制行为。

**学习目标**
- 慢启动（Slow Start）
- 拥塞避免（Congestion Avoidance）
- 快速重传（Fast Retransmit）
- 快速恢复（Fast Recovery）
- 拥塞窗口（cwnd） vs 接收窗口（rwnd）

**与后端的连接**  
接口在并发高时为什么变慢？—— 拥塞控制是底层原因之一。

**交付笔记**  
[[TCP拥塞控制：网络塞车了怎么办]]

---

### 模块六：HTTPS 与加密 —— 数据是怎么保密的？

> ⏱ 约 4~5 天 · 理论 50% + 实践 50%

**任务**  
Wireshark 抓包对比 HTTP 和 HTTPS，配置 SSLKEYLOGFILE 解密自己的 HTTPS 流量，观察 TLS 握手。

**学习目标**
- 对称加密 vs 非对称加密
- TLS 1.2 / 1.3 握手过程
- 数字证书与 CA 信任链
- HTTPS 的性能开销与优化

**与后端的连接**  
JWT 签名原理、OAuth2 的 Token 传输安全、配置 SSL 证书。

**交付笔记**  
[[HTTPS与加密：你的数据是这样被保护的]]

---

### 模块七：网络分层模型 —— 把所有知识串起来

> ⏱ 约 3~4 天 · 理论 60% + 实践 40%

**任务**  
回顾前 6 个模块的抓包数据，按 OSI / TCP 分层模型重新标注每个报文。

**学习目标**
- OSI 七层模型 vs TCP/IP 四层模型
- 各层协议、设备、数据单元名称（PDU）
- 封装与解封装过程
- 各层如何协作完成一次通信

**交付笔记**  
[[网络分层模型：一张图串起所有协议]]
- 附完整的协议栈分层图
- 从应用层到物理层，逐层标注你抓过的包

## 四、协作方式

每进入一个模块，你只需说 **"开始模块 X"**，我就会：

1. **引导**你完成该模块的核心实践任务
2. **答疑**你在动手过程中的疑问
3. **产出笔记**：任务完成后，根据你的理解和抓包结果，生成该模块的 Markdown 笔记文档
4. **你审查并修改**，变成你自己真正的知识沉淀

遇到文字不好理解的抽象概念，会提示你看对应 **湖科大教书匠** 视频段作为补充。
