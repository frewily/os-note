## 一、网络分层与协议分工

### 1. HTTP、TCP、IP、以太网分别负责什么？

- **HTTP**：应用层协议，规定请求和响应的格式与语义，负责表达“要访问什么、提交什么数据、服务器返回什么结果”。
- **TCP**：传输层协议，在两个应用之间提供可靠、有序的字节流传输，并通过端口号区分具体应用。
- **IP**：网络层协议，使用 IP 地址标识主机，并负责让数据包跨越多个网络到达目标主机。
- **以太网**：链路层技术，在局部网络中传输数据帧，使用 MAC 地址识别网卡和当前链路上的下一跳设备。

面试简答：

> HTTP 管内容，TCP 管可靠传输，IP 管跨网络找主机，以太网管局部网络发帧。

### 2. 数据是怎样逐层封装的？

发送端通常经历以下过程：

```text
HTTP 数据
  ↓ TCP 添加 TCP 首部
TCP 段（Segment）
  ↓ IP 添加 IP 首部
IP 包/数据报（Packet / Datagram）
  ↓ 以太网添加帧头和帧尾
以太网帧（Frame）
```

TCP 首部常见信息：

- 源端口、目标端口；
- 序列号、确认号；
- SYN、ACK、FIN 等控制标志；
- 接收窗口；
- 校验和。

IP 首部的核心地址是源 IP 和目标 IP。链路层帧的核心地址是源 MAC 和目标 MAC。

### 3. 最终目标 IP 与下一跳 MAC 的区别

访问外网时：

- IP 首部中的目标 IP 通常仍然是远程服务器的 IP；
- 当前以太网帧中的目标 MAC 通常是默认网关的 MAC。

默认网关收到当前链路上的帧后，会根据目标 IP 继续转发。数据每经过一个局部网络，链路层的 MAC 地址可能重新变化；IP 层的最终目标通常不变。

如果目标主机与发送主机处于同一局域网，发送方通常会通过 ARP 获取目标主机的 MAC；如果目标主机在外网，发送方通常获取的是默认网关的 MAC。

## 二、TCP 端口与连接标识

### 1. TCP 如何区分同一台主机上的不同应用？

TCP 使用端口号区分具体应用。通信双方分别有源端口和目标端口：

- IP 地址：定位主机；
- 端口号：定位主机上的网络应用。

一条 TCP 连接通常可以由四元组标识：

```text
源 IP + 源端口 + 目标 IP + 目标端口
```

常见端口约定：HTTP 通常使用 `80`，HTTPS 通常使用 `443`。

## 三、HTTP 状态码

### 1. 常见状态码

| 状态码 | 含义 | 常见解释 |
| --- | --- | --- |
| `200 OK` | 成功 | 服务器成功处理请求并返回正常响应 |
| `301 Moved Permanently` | 永久重定向 | 资源已经永久迁移，通常通过 `Location` 告知新地址 |
| `404 Not Found` | 资源不存在 | 服务器找不到请求的路径或资源 |
| `500 Internal Server Error` | 服务器内部错误 | 服务器处理请求时发生未妥善处理的异常或内部故障 |

### 2. 404 是否代表 TCP 连接失败？

不是。

通常流程是：

1. TCP 连接建立；
2. 客户端发送 HTTP 请求；
3. HTTP 服务端找不到对应资源；
4. 服务端返回 `404` 响应。

因此，收到 HTTP 状态码通常说明请求已经到达某个 HTTP 服务并获得了应用层响应。若 TCP 连接失败，通常收不到 HTTP 状态码，而会出现连接超时、连接被拒绝或网络不可达等错误。

## 四、与 Agent 项目的联系

前端请求 Java 后端时，可以这样解释：


1. 前端在 HTTP 请求中表达接口路径、参数和请求体；
2. TCP 通过端口把数据交给目标 Java 服务，并负责可靠传输；
3. IP 负责把数据包送到目标主机；
4. 如果 Java 服务位于外网，当前局域网帧先发送给默认网关；
5. Java 服务处理请求后，再沿相反方向返回 HTTP 响应。

这里的“理解并能复述”不等于已经完成抓包验证。后续需要结合 Wireshark 或实际接口请求，核对 HTTP、TCP、IP 字段在真实报文中的表现。
