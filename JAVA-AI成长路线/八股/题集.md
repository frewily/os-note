## D1 面向对象、接口与抽象类、异常体系

### D1-1 面向对象三大特性？各自解决什么问题？（🟡 理解但不流畅）

**考察重点**：封装/继承/多态定义 + 实际意义，而不是背名词

**项目联系**：DTO/VO/Service 分层、Controller 只收参返回

**回答骨架**：
- **封装**：隐藏内部实现，对外暴露方法接口 → 降低耦合、保护数据不被乱改
  - 项目：Service 封装业务细节，Controller 只负责收参/返回；DTO/VO 隔离内部实体，不让数据库实体直接暴露给前端
- **继承**：子类复用父类代码并可扩展 → 消除重复
  - 注意：继承破坏封装、耦合高，优先用**组合**；IS-A 才用继承
- **多态**：同一行为，不同子类有不同实现（父类引用指向子类对象）→ 提高扩展性，符合开闭原则
  - 三条件：继承/实现 + 方法重写 + 父类引用指向子类对象
  - 项目：面向接口编程（Service 接口 + 多实现），策略模式

**本轮复述记录**：
- 已掌握：封装是隐藏细节、暴露接口，可降低耦合并保护数据；多态是“编译看左边、运行看右边”，同一接口可以有不同实现。
- 待加强：继承不只是代码复用，还要强调 `is-a` 类型关系；多态要补充“继承/实现、重写、父类引用指向子类对象”三个条件，以及新增实现时调用方无需修改。

### D1-2 接口和抽象类的区别？怎么选？

**考察重点**：设计层面区别（is-a vs can-do）、JDK8+ 接口变化

**项目联系**：Service 接口 + Impl 为什么这么拆

**回答骨架**：
- **抽象类**：`is-a` 关系，单继承；可以有构造器、成员变量、具体方法；描述"**是什么**"
- **接口**：`can-do` 关系，多实现；JDK8 前只能抽象方法，JDK8 可 `default`/`static`，JDK9 可 `private`；描述"**能做什么**"
- **怎么选**：能用接口优先接口；需要复用代码/共享状态/模板方法 → 抽象类
- 项目：Mapper/Service 拆接口 + 实现，便于替换、也才能被 JDK 动态代理（AOP 需要）

### D1-3 Java 异常体系？项目里怎么处理异常？

**考察重点**：Throwable 两大分支、受检/非受检、Spring 事务回滚规则

**项目联系**：全局异常处理器、业务异常设计

**回答骨架**：
- `Throwable` → **Error**（JVM 级，OOM/StackOverflow，不处理）+ **Exception**（可处理）
- `Exception` → **受检异常**（编译期强制处理，IOException/SQLException）＋**非受检 RuntimeException**（NPE、IllegalArgumentException）
- 关键坑：**Spring 事务默认只对 RuntimeException/Error 回滚**，受检异常不会回滚 → `@Transactional(rollbackFor = Exception.class)`
- 项目：`@RestControllerAdvice` + `@ExceptionHandler` 统一兜底；自定义 `BizException extends RuntimeException`，业务错误直接抛，避免受检异常层层 `throws` 污染接口
- 常见坑：catch 了异常却不打日志/不抛；用异常做流程控制（性能差）
