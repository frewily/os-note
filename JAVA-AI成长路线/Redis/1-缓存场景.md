# 缓存场景

---

## 核心

使用缓存时最常遇到的三个问题——穿透、击穿、雪崩，各自的原因和解决方案不同。

---

## 缓存穿透

**现象**：查询一个**不存在的数据**，缓存没有，数据库也没有。每次请求都打到数据库。

```java
// 用户查一个不存在的 ID
GET user:9999          → 缓存没有
SELECT * FROM users WHERE id = 9999  → 数据库也没有（空结果）
GET user:9999          → 缓存还是没有（因为数据库也没有）
SELECT * FROM users WHERE id = 9999  → 数据库又被查一次
// 恶意攻击可以用大量不存在 ID 打垮数据库
```

**解决方案**：

```java
// 方案一：缓存空值（简单有效）
Object value = redis.get("user:9999");
if (value == null) {
    User user = userMapper.findById(9999);
    if (user == null) {
        redis.set("user:9999", "NULL", 60);  // 空值也缓存，短期过期
    } else {
        redis.set("user:9999", user);
    }
}

// 方案二：布隆过滤器（更优雅，但需要维护）
// 在 Redis 之外维护一个布隆过滤器，判断 id 是否可能存在
if (!bloomFilter.mightContain(9999)) {
    return null;  // 肯定不存在，直接返回
}
```

## 缓存击穿

**现象**：一个**热点 key** 过期瞬间，大量并发请求同时打到数据库。

```java
// 某个热点数据（如首页广告配置），缓存过期瞬间
// 1000 个请求同时到达：
Thread 1-1000: GET hot_key → 返回 null（缓存刚过期）
Thread 1-1000: 全部去查数据库
→ 数据库瞬间被打满
```

**解决方案**：

```java
// 方案一：互斥锁（setnx）
String lockKey = "lock:hot_key";
Boolean locked = redis.setIfAbsent(lockKey, "1", 3, TimeUnit.SECONDS);
if (locked) {
    // 拿到锁的线程去查数据库
    Object data = db.query(...);
    redis.set("hot_key", data, 3600);
    redis.delete(lockKey);
    return data;
} else {
    // 没拿到锁的线程等待后重试
    Thread.sleep(100);
    return redis.get("hot_key");  // 等拿到锁的线程写回缓存
}

// 方案二：热点 key 永不过期（后台异步刷新）
// 不设过期时间，后台起一个定时任务定期更新
```

## 缓存雪崩

**现象**：大量 key **同时过期**，或者 Redis 宕机，大量请求打到数据库。

```java
// ❌ 大量 key 同时过期
redis.set("key1", data1, 3600);  // 一个小时后过期
redis.set("key2", data2, 3600);  // 同一时间
redis.set("key3", data3, 3600);  // 全部同时过期
// 一个小时后，所有 key 同时失效，所有请求一起打到数据库

// ✅ 过期时间加随机值，分散过期时间
int baseTtl = 3600;
int randomTtl = baseTtl + new Random().nextInt(300);  // 3600~3900 随机
redis.set("key1", data1, randomTtl);
redis.set("key2", data2, baseTtl + random.nextInt(300));
redis.set("key3", data3, baseTtl + random.nextInt(300));
```

---

## 三种场景对比

| | 穿透 | 击穿 | 雪崩 |
|--|------|------|------|
| **原因** | 查不存在的数据 | 热点 key 过期 | 大量 key 同时过期 / Redis 挂了 |
| **影响** | 数据库被无效请求打满 | 数据库被高并发打满 | 数据库被高并发打满 |
| **缓存空值** | ✅ 解决 | ❌ 不适用 | ❌ 不适用 |
| **互斥锁** | ❌ 不适用 | ✅ 解决 | ❌ 不适用 |
| **过期随机化** | ❌ 不适用 | ❌ 不适用 | ✅ 解决 |
| **布隆过滤器** | ✅ 解决 | ❌ 不适用 | ❌ 不适用 |
| **永不过期+异步刷新** | ❌ 不适用 | ✅ 解决 | ✅ 解决 |

## 项目关联

| 场景 | 说明 |
|------|------|
| **缓存穿透** | 用户查一个不存在的对话 ID，缓存空值避免打到数据库 |
| **缓存击穿** | AI 模型配置信息是热点数据，过期时锁住只让一个线程回源 |
| **缓存雪崩** | 所有缓存 key 的过期时间加随机值，避免同时失效 |
