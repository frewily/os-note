# 日常流程

---

## 核心

日常开发就是"拉最新代码 → 开发 → 提交 → 推送"的循环。

---

## 标准开发流程

```bash
# ① 开始工作前：拉取最新代码
git pull

# ② 写代码... 写完后查看修改了哪些文件
git status

# ③ 确认无误后，加入暂存区
git add <修改的文件>              # 一个个加
git add .                        # 或一次加所有

# ④ 提交到本地
git commit -m "feat: 完成了XXX功能"

# ⑤ 推送到远程（多人协作时，推之前最好再 pull 一次）
git pull                         # 避免别人已推了新代码
git push                         # 推送
```

---

## 什么时候做什么

```bash
# 开始新功能
git pull                        # 拿最新代码

# 改完一段代码，想保存进度
git add <文件>
git commit -m "wip: 完成了XX部分"

# 下班前
git add .
git commit -m "feat: XXX功能完成"
git push                        # 推到远程，明天继续

# 第二天上班
git pull                        # 拉到最新
```

---

## 推荐习惯

- **频繁提交**：一个功能点完成就 commit，不要攒一大堆再提交
- **提交前跑一下测试**：确保不会把坏的代码推上去
- **推之前先 pull**：避免对方的提交和自己的冲突
- **写有意义的 commit message**：`"修复了用户登录时 token 过期没正确处理的问题"` 比 `"fix"` 好得多
