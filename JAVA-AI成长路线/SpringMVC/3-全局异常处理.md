# 全局异常处理

---

## 核心

`@ControllerAdvice` + `@ExceptionHandler` 统一收口所有异常，避免每个 Controller 重复写 try-catch。

---

## 基本用法

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    // 处理自定义业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusiness(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }
    
    // 处理参数校验失败
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getAllErrors()
                .stream().map(DefaultMessageSourceResolvable::getDefaultMessage)
                .collect(Collectors.joining("; "));
        return Result.error(400, msg);
    }
    
    // 处理未登录
    @ExceptionHandler(UnauthorizedException.class)
    public Result<?> handleUnauthorized(UnauthorizedException e) {
        return Result.error(401, e.getMessage());
    }
    
    // 处理参数类型不匹配（如字符串传成数字）
    @ExceptionHandler(IllegalArgumentException.class)
    public Result<?> handleIllegalArgument(IllegalArgumentException e) {
        return Result.error(400, "参数不合法");
    }
    
    // 兜底——捕获所有未处理的异常，返回 500
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        log.error("系统异常", e);  // 记录错误栈
        return Result.error(500, "服务繁忙，请稍后再试");
    }
}
```

---

## 执行流程

```
Controller 方法抛出异常
       ↓
有没有对应的 @ExceptionHandler？
  ├─ 有 → 执行该处理方法，返回统一响应
  └─ 无 → 继续往上抛
            ↓
  Tomcat 返回默认 500 错误页面（不友好）
```

**这就是为什么一定要有一个兜底的 `Exception` 处理器**——漏掉的异常不会自动变成友好提示，Tomcat 会返回一个默认错误页面或堆栈信息。

## 业务异常使用模式

```java
// 业务层抛出异常
@Service
public class OrderService {
    
    public void createOrder(OrderDTO dto) {
        if (dto.getUserId() == null) {
            throw new BusinessException(400, "用户ID不能为空");
        }
        if (dto.getAmount() == null || dto.getAmount().compareTo(BigDecimal.ZERO) <= 0) {
            throw new BusinessException(400, "金额不合法");
        }
        // 正常业务逻辑
    }
}

// Controller 层不需要 try-catch——异常会由全局处理器统一处理
@PostMapping("/orders")
public Result<Order> createOrder(@RequestBody @Valid OrderDTO dto) {
    return Result.success(orderService.createOrder(dto));
}
```

**效果**：Service 层专注于业务逻辑，出问题时抛异常；Controller 层专注于接收请求返回响应；全局处理器负责异常转成友好提示。

## 常见的异常映射

| 异常 | 状态码 | 说明 |
|------|--------|------|
| `BusinessException` | 400 / 自定义 | 业务逻辑错误 |
| `MethodArgumentNotValidException` | 400 | 参数校验失败 |
| `IllegalArgumentException` | 400 | 参数不合法 |
| `UnauthorizedException` | 401 | 未登录 |
| `AccessDeniedException` | 403 | 权限不足 |
| `NoSuchElementException` | 404 | 资源不存在 |
| `Exception`（兜底） | 500 | 服务器内部错误 |
