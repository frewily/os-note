> 原则：区分“接触过”“在帮助下能完成”“能够独立完成”和“能够解释、排查与设计”。代码存在、项目能启动或 AI 已经实现，不等于本人已经掌握。

## 1 基本情况

- 学校：合肥工业大学宣城校区，211。
- 专业与年级：软件工程，大二刚开学，预计 2029 届。
- 当前倾向：优先尝试本科就业，同时保留以后重新评估读研的可能性。
- 可投入时间：正常学习阶段每天可持续投入约 6 至 8 小时自主学习；考试阶段另行调整。

## 2 求职目标

### 2.1 当前定位

- 主线：Java 后端实习。
- 副线：Agent 应用开发、AI 应用后端和 RAG 工程相关实习。
- 第一段实习不执着公司规模和薪资上限，核心要求是能够参与真实开发、获得反馈、形成可诚实写入简历的个人产出。
- 不把“拿到实习”本身当作成功；如果主要工作是长期重复测试、数据标注、机械录入或与目标方向无关的杂活，则价值有限。

### 2.2 长期偏好

- 长期重视工作与生活平衡；大二寒假及大二下投递时，大厂作为冲刺目标、中厂作为重点目标、高质量中小厂作为保底，不执着于公司标签。
- 如果国内公司能够提供相近的工作与生活平衡，也可以接受。
- 外企仍作为大三阶段的长期目标；当前技术和英语尚未达到针对外企集中准备的阶段，但大二上按更高的算法、基础和项目标准为国内大厂实习做准备。
- 长期能力定位不是“只会 Java 框架”，而是“以 Java 为主要工具、具备计算机基础和 AI 系统集成经验的后端工程师”。

## 3 能力等级定义

| 等级 | 含义 |
| ---: | --- |
| 0 | 基本没学过 |
| 1 | 看过概念，无法稳定使用 |
| 2 | 在教程、模板或 AI 帮助下能够使用 |

### 4.2 独立开发能力

当前真实边界：

- 参考模板后，可能完成 Spring Boot 增删改查、参数校验和异常处理；尚不能稳定从零搭建。
- 参考模板后，可能设计简单关联表；尚不能独立完成完整数据库建模。
- 不能独立使用 Redis 设计缓存或限流。
- 能阅读部分报错日志，但能否定位并解决真实问题尚未稳定验证。
- 参考模板后，可能编写简单单元测试；尚不能独立设计测试体系。
- 不能独立编写 Dockerfile 或 Docker Compose。
- Git 分支、冲突解决和提交整理尚不熟练。

因此，当前更准确的阶段是“有一定使用经验，但独立交付能力尚未形成”，不能描述为已经具备完整后端业务开发能力。

## 8 当前优先级

当前优先级不按“哪件事最焦虑”排序，而按对独立能力和第一段实习质量的影响排序：

1. 大二上优先系统沉淀 Java、JVM、操作系统、计算机网络、数据库、并发和算法；Agent 项目改为 AI 分阶段优化、本人低频验收与关键架构学习。
2. 补齐 Java 后端核心基础，重点是 JVM、并发、Spring、MySQL 和 Redis。
3. 建立操作系统和计算机网络的面试骨架，并通过亲手实验重新验证计网知识。
4. 继续算法训练，提高常见简单题和中等题的独立完成率。
5. 寒假及大二下学期开学前后再评估简历和投递准备，达到最低门槛后同时试投大厂、中厂和高质量中小厂，通过真实反馈调整准备。
6. 课程成绩保持不挂科，并妥善处理考试和学校出勤要求。

第一段实习是阶段目标，不是压倒其他能力建设的每日学习模块。不能为了尽快拥有一段实习而接受明显无法成长、无法形成个人产出的岗位。

## 9 投递与入职门槛

### 9.1 小规模试投门槛

满足以下大部分条件后开始小规模试投：

- 能脱稿讲清 Agent 项目的整体架构和一条主要请求链路。
- 至少完成一次真实端到端业务验证。
- 能诚实说明项目来源和个人贡献边界。
- Java、集合、Spring、MySQL、Redis、并发、JVM、操作系统和计网具备第一轮高频问题框架。
- 常见简单题可以独立完成，常见中等题能识别部分题型并写出主要思路。
- 有一版不夸大项目贡献的中文简历。

首轮试投选择少量有代表性的岗位，覆盖冲刺大厂、重点中厂和高质量中小厂，用于观察简历反馈和面试缺口；具体数量和比例在寒假月计划中根据当时岗位开放情况确定，不要求拿到就去。

### 9.2 扩大投递门槛

- 能稳定讲解一个主项目 10 至 15 分钟。
- 拥有至少一项本人主导、能够展示代码和验证过程的改动。
- 能独立完成一个基础 Spring Boot 业务接口和简单数据库设计。
- 能回答目标岗位最常见的基础问题，并完成至少一次模拟面试。
- 根据试投反馈完成一轮简历和知识补漏。

### 9.3 实习质量判断

“有正式导师”不是唯一标准。中小团队可能没有正式 mentor 制度，但至少应有一位更有经验的开发者提供任务说明、代码评审或问题反馈。

面试或沟通时重点确认：

1. 实习生入职后前两至四周会参与什么具体任务。
2. 是否进入真实代码仓库和正常研发流程。
3. 谁负责需求说明、代码评审和问题反馈。
4. 实习生过去通常做功能开发、测试开发，还是长期机械工作。
5. 使用的技术栈与目标方向是否相关。
6. 是否能够形成明确、可展示且可诚实写入简历的个人产出。
7. 薪资是否能够覆盖通勤、租房等额外成本。
8. 到岗要求是否与考试、学校出勤和个人健康冲突。

如果岗位没有正式导师，但能进入真实项目、有开发者评审代码并持续获得反馈，仍然可能是值得去的实习。

## 10 当前风险

- 项目功能完成度高于本人掌握程度，面试追问风险较大。
- 对 AI 和模板依赖较强，独立实现、方案选择和验证能力不足。
- 多线程、JVM、操作系统是明显知识空缺。
- 计网旧笔记较多，但真实掌握程度被高估过。
- 黑马点评辨识度低且长期未复习，不能直接作为成熟项目使用。
- 如果过早入职低质量岗位，可能挤压当前最需要的基础和项目接管时间。
- 如果一直等待“完全准备好”再投递，也会缺少真实市场反馈。

对应策略是“准备与试投分阶段”：先建立最低能力门槛，再小规模试投；根据反馈扩大投递，而不是固定日期海投或无限延期。

当前采用“大二上基础沉淀 → 寒假前综合验收 → 寒假及大二下求职转换”的节奏。大二上不以固定日期投递为目标，优先建立 Java/JVM/OS/计网/数据库/算法的长期学习与间隔复习体系；项目由 AI 分阶段优化，本人保留范围判断、运行验收和关键架构理解。寒假前再根据课程、六级和技术状态决定简历收口与小规模试投时间，不承诺固定日期获得 Offer。

## 11 阶段复盘规则

每两周重新检查一次：

- 哪些能力已经从“在帮助下能完成”升级为“能独立完成”。
- 哪些项目结论有真实运行、代码、测试或复述证据。
- 算法独立完成率是否提高。
- 是否满足试投或扩大投递门槛。
- 最近接触的岗位是否真的符合成长和成本底线。

能力升级必须补充证据；单纯阅读资料、生成笔记或看懂 AI 解释，不自动提高等级。
