会调 LangChain、会写 Prompt 还不够，未来需要进入真正的 AI 工程化阶段。

## 六、分阶段执行路线

### 2026 暑假（7.13 - 9 月）—— 最关键阶段

这是整个大学阶段非常关键的一个窗口。大二开始竞争会越来越激烈，需要在此之前建立真正的技术底座。

> **当前状况**：计网核心模块已基本完成（TCP/IP/HTTPS/DNS/抓包实战），面试前再集中复习即可。暑假的核心矛盾是**算法薄弱（50 题以下）+ JVM 未入门**。

**策略**：暑假拆成前后两期，前期猛攻算法 + JVM，后期转向项目 + 面试准备。

---

#### 第一阶段（7.13 ~ 8 月中旬）：算法 + JVM

这是暑假的决胜期。

**每日时间分配建议（按每天 6~8 小时估算）：**

```
算法（40%）：  2.5 小时   2 道题 + 复盘总结
JVM（35%）：  2 小时     系统学习 + 笔记整理
八股恢复（15%）：1 小时  HashMap 恢复 + JVM 八股提前预习
英语（10%）：  30~45 分钟 英文技术视频 / Shadowing
```

> **原则**：每天核心就三件事——算法、JVM、八股。算法不求量求质，每天 2 题吃透。
>
> **💡 开源项目**：Phase 1 不要碰。算法 + JVM 打好基础后再考虑，开源项目的收益是"从 80 分到 90 分"，现在优先级还不够。

**目标 1：算法（Hot100 剩余 60 题）**

简单题已刷完，剩余以中等题为主。当前重点不是数量，而是**套路识别能力**。

**前 2 周（7.13~7.26）—— 按题型分类刷**
- 数组 / 链表 / 哈希表
- 重点：手写能力、时间复杂度意识、每道题看最优解

**后 4 周（7.27~8.17）—— 核心算法套路**
- 双指针 / 滑动窗口 / 二分 / DFS & BFS / 回溯 / 贪心
- 堆 / 前缀和 / 单调栈 / 动态规划（基础）

**每日节奏：**
```
做 2 道新题（40~50 min × 2）
→ 看最优解，和自己的解法对比（15 min）
→ 把套路总结到笔记里（15 min）
→ 总耗时约 2~2.5h
```

**目标：8 月中旬前 Hot100 第一轮刷完**

> 能独立写出来的题才算刷过。不会的题看完答案后，第二天重做一遍。

**目标 2：JVM 入门**
- JVM 内存结构（堆 / 栈 / 方法区）
- GC 基础（哪些区域需要 GC、可达性分析）
- 类加载机制（双亲委派模型）

> 目标：建立"Java 为什么这样运行"的感觉。

**🎯 八股趁热打铁**：学完 JVM 后，花 1~2 天集中看 JVM 高频面试题（内存分区、GC 算法、双亲委派），你会发现大部分都能答上来了。

**目标 3：八股恢复**

快速恢复期末前学过的 HashMap / ConcurrentHashMap 八股：

- 第 1 天：看旧笔记出声说一遍
- 第 2 天：再出声说一遍
- 第 4 天：检查是否流畅

同时 JVM 学到哪，就跟进看对应的八股题，把"趁热打铁"这个动作做扎实。

**💡 计网怎么处理**

计网核心已学完，暂时放下。有两个和后端强相关的知识点可选快速收掉（各 1 小时内）：

- **TIME_WAIT 调优**：面试高频，`netstat -an | grep TIME_WAIT` 看一眼
- **HTTP 缓存机制**：304、Cache-Control，在你项目 API 中能用上

不急的话面试前再翻笔记也行。

**第一阶段复盘（8 月中旬）：**
- Hot100 第一轮刷完了吗？能独立写出来的有几成？
- JVM 的内存分区和 GC 流程能不能用自己的话讲清楚？
- 八股恢复了吗？
- 第二阶段是否需要调整？

---

#### 第二阶段（8 月中旬 ~ 9 月）：AI 项目升级 + 面试准备

第一阶段结束后，算法和 JVM 已基本到位，后半段转向工程深度和面试能力。

**每日时间分配建议（按每天 6~8 小时估算）：**

```
项目（40%）：  2.5~3 小时  AI 项目工程化 + 调试
算法（30%）：  2 小时      保持手感 + 二刷错题
八股系统化（20%）：1.5 小时  JVM 八股 + 计网八股背诵
英语（10%）：  30~45 分钟  英文技术视频 / Shadowing
```

> **原则**：项目权重上升，算法降为维持。八股开始系统化背诵，把第一阶段学的东西转化成面试表达。

**目标 1：AI 项目工程化升级**

在现有 AI 客服系统基础上增加工程能力。每个功能不只是"加功能"，而是通过它反向驱动工程基础成长：

| 项目功能 | 牵出的工程基础 |
|---------|--------------|
| **SSE 流式输出** | HTTP 长连接、TCP、Netty 异步 |
| **历史上下文** | Redis 数据结构、Token 管理、数据库设计 |
| **用户系统 + JWT** | Spring Security、拦截器链、Session vs Token |
| **Prompt 管理** | 模板模式、配置中心思想、版本管理 |
| **向量数据库** | RAG 链路、Embedding、Chunk 策略、Recall |
| **并发请求处理** | 线程池、异步编程、队列 |
| **Docker 部署** | Linux、Nginx、容器化、CI/CD |

> **这样做的好处**：你不是在"学计网、学 Redis"——你是在"解决 AI 项目的工程问题"。基础知识变成你的工具，而不是理论负担。

**🎯 开源准备**：以上工程特性完成后，你的项目就具备了"可开源"的基础。花几天时间做几件事，会大幅提升 GitHub 页面的质量：

- 写一份完整的 **README**（项目介绍 / 架构图 / 技术栈 / 快速启动）
- 配置 **GitHub Actions** 实现自动构建和测试
- 补 **单元测试**（JUnit + Mockito）
- 清理代码结构，去掉死代码，规范命名

> 这个过程本身就在训练工程能力。做完后如果还有余力，再去 **Spring AI** 提一个文档或示例的 PR，作为你的第一个开源贡献。

**🎯 关于 黑马点评（周末辅助项目）**

这是你之前跟过的教程项目（秒杀/优惠券/Redis 缓存），虽然暂时不是主力项目，但其中几个模块面试高频。建议在 Phase 2 每周末花半天（2~3 小时）重新过一遍，**不再跟做，只挑最有价值的部分回看**：

| 模块 | 值得重新看什么 | 为什么 |
|------|--------------|--------|
| **Redis 缓存篇** | 缓存穿透/击穿/雪崩的处理方式、分布式锁实现 | 面试必考，且 AI 客服项目也会用到 |
| **秒杀篇** | 乐观锁、事务边界、库存超卖问题 | 并发场景典型，面试高频 |
| **项目整体** | 模块划分、异常处理、统一返回值 | 了解一个完整项目的规范 |

> **vibe coding 时代，项目学习要问自己三个问题**：① 这个模块解决的是什么工程问题？② 为什么这样设计而不是另一种方式？③ 如果让 AI 来写，我需要在 prompt 里描述什么？——前两个问题训练你的系统设计能力，第三个问题训练你驾驭 AI 的能力。

**目标 2：八股系统化**

将第一阶段学过的知识转化为面试回答：

- **JVM 八股**：面试常考的 JVM 内存分区、GC 算法、双亲委派。结合第一阶段的学习内容，整理成 3~4 句话的面试回答
- **计网八股**："从输入 URL 到页面展示"全过程、TCP 三次握手为什么是三次、HTTP2 多路复用等
- 每天选 1 道，出声说 3 遍

**第二阶段复盘（9 月开学前）：**
- 项目相比暑假前，增加了几个工程特性？能讲清楚每个的技术细节吗？
- 八股能不能流畅回答出来？
- 暑假整体目标达成了吗？大二上的重点需要怎么调？

## 七、需要补充的能力版图

以下是在两份文档基础上建议补充的方向：

### 7.1 测试意识（工业级必备）

- **单元测试**：JUnit + Mockito
- **集成测试**
- 培养 TDD（测试驱动开发）意识

- **GitHub Actions**：自动化构建和测试
- **Docker Compose**：多容器编排

### 7.3 Spring AI

你的主力语言是 Java，相比 Python LangChain + Java 后端两套并行，**Spring AI** 可以让 AI 集成更统一、更工程化。

> [Spring AI 官方项目](https://spring.io/projects/spring-ai)

**切入时机**：不要急着现在切过去。建议先用 LangChain 把暑假的 AI 项目升级做完，对 AI 工作流有了完整体感之后，再在**大二寒假**尝试用 Spring AI 重写 1~2 个核心功能。这样既理解了 AI 概念本身，又能对比两种实现的差异，理解更深。

### 7.5 Vibe Coding 时代，项目应该学什么

AI 能生成大量代码的今天，项目学习的重心需要从"写代码"转向"做决策"。一个项目里真正值得花时间研究的，按价值排序：

| 价值 | 值得学 | 不值得学 |
|------|--------|---------|
| ⭐⭐⭐⭐⭐ | **架构设计**：模块怎么分、层怎么划、接口怎么定义 | Controller 增删改查（AI 能写） |
| ⭐⭐⭐⭐ | **系统决策**：为什么用缓存、为什么选这个中间件 | 配置文件的拼写（AI 能写） |
| ⭐⭐⭐⭐ | **非功能性设计**：并发怎么处理、异常怎么统一管理 | 实体类的 Getter/Setter（AI 能写） |
| ⭐⭐⭐ | **部署与运维**：Docker 怎么写、Nginx 怎么配置 | 注解的用法（查文档比背更快） |
| ⭐⭐ | **测试策略**：哪些场景需要写测试、怎么 mock | 重复的业务 CRUD |

**学项目的正确姿势**：拿到一个项目，先看 README 和架构图，搞清楚"这个系统解决什么问题、模块之间怎么通信"，再去读核心接口的设计，最后才看具体实现。不要反着来——从 Controller 一路看到 Mapper，看完就忘。

> **面试时能说清楚"为什么这么设计"，比说清楚"怎么写的"要值钱得多。**

## 九、需要避免的陷阱

### ⚠️ AI 焦虑

```
今天学 LangGraph → 明天学 MCP → 后天学 Multi-Agent
→ 结果：什么都懂一点，什么都不深入
```

**对策**：选定一个方向深入，不要追每个热点。

### ⚠️ 八股成瘾

八股是面试工具，不是真正能力。真正重要的是理解"为什么这样设计""为什么这样优化"。

### ⚠️ 疯狂堆项目

```
做 10 个 Demo  <  做 1~2 个有深度的项目
```
