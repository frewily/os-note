# 大二上至寒假 Java 后端与 Agent 技术沉淀整体规划

> 制定日期：2026-09-18  
> 适用周期：2026-09-18 至寒假前，暂按 2027 年 1 月中旬估算；学校校历明确后调整终点。  
> 定位：学期路线图，不承担每日任务管理。每月月初依据课程、考试、六级安排和上月结果，另行制定当月详细计划。

## 1. 阶段目标

大二上不以短期投递和尽快获得实习为目标，优先完成技术基础沉淀。准备标准同时面向大厂和中厂 Java 后端/AI 应用后端实习，不因当前经验不足而提前放弃大厂；寒假及大二下学期开学前后，再根据课程、可到岗时间和能力验收结果，决定项目收口、简历制作与分层投递时间。

寒假前希望形成以下结果：

1. Java 后端基础形成第一轮体系，重点覆盖 Java 集合、并发、JVM、Spring、MySQL 和 Redis。
2. 操作系统与计算机网络形成连续知识骨架，并建立稳定的间隔复习机制。
3. 算法从“看过题解会做”逐渐推进到能识别常见题型、独立完成部分中等题并稳定复做。
4. Agent 项目由 AI 分阶段优化至少一个稳定里程碑；本人能说明项目来源、整体架构、核心链路、关键取舍和真实验证范围。
5. 黑马点评保持为 Redis、MySQL、并发知识的辅助项目，本学期不与 Agent 项目并行大规模重构。
6. 寒假前完成一次综合验收，并据此制定寒假求职转换计划，而不是按预设日期强行投递。
7. 为大厂常见筛选要求提前准备算法、计算机基础、Java 深度、项目追问和规范求职材料，同时保留中厂与高质量中小厂选择。

六级由本人根据考试时间单独安排。本规划只在六级、期中和期末压力增大时主动降低技术任务量，不安排具体六级任务。

## 2. 优先级

### 第一优先级：长期基础

- Java 核心与并发
- JVM
- MySQL、Redis、Spring
- 操作系统
- 计算机网络

### 第二优先级：持续训练

- 算法题型识别、独立思考、错题复做
- 技术内容的脱稿表达和间隔复习
- 面向大厂机试和技术面的限时编码、复杂度分析与综合追问

### 第三优先级：低频项目

- Agent 项目分阶段 AI 优化、运行验收和架构学习
- 黑马点评按基础知识主题回看，不主动扩展大量功能

### 当前暂不做

- 不制定固定投递数量或 Offer 截止日期。
- 不在大二上课程密集期进行海投。
- 不因为以大厂为冲刺目标，就只投大厂或用公司规模代替岗位质量判断。
- 不同时大规模重构两个项目。
- 不以“企业级”“高并发”等没有测试证据的表述包装项目。
- 不为了项目手搓大量模板代码，也不把 AI 生成和项目能运行等同于本人掌握。

## 3. 固定学习机制

### 3.1 间隔复习

Java 八股、JVM、操作系统和计算机网络统一执行：

- 当天：理解新内容，完成简短笔记和首次脱稿复述。
- D+1：不看笔记回忆主线，回答 2 至 3 个基础问题。
- D+3：回答常见追问，联系一个 Java、Linux 或项目场景。
- D+7：混合抽查，重点纠正错误和含糊表达。
- D+14：保留性复习；稳定内容降低频率，不稳定内容重新进入 D+3 队列。

掌握状态分为“看过、理解、能脱稿解释、能应用或验证”，笔记存在不能直接标记为掌握。

### 3.2 算法

- 每周学习 5 至 6 天，但根据课程动态降低题量。
- 空闲日原则上 2 道新题加 1 道复习题。
- 课程密集日允许只做 1 道新题或 1 道复习题。
- 陌生中等题先独立思考 20 至 30 分钟，再获取局部提示。
- 记录题型识别、关键思路、边界条件和错误原因，并在次日、7 天后复做重点题。

### 3.3 项目

- 平时每周安排 1 至 2 个项目学习块，每次 60 至 90 分钟；考试或六级冲刺阶段可以暂停新改动。
- AI 可以负责分析、重构、编码、测试和文档，但每次只交付一个边界明确的阶段。
- 每个阶段必须提供：目标与范围、核心变更、测试结果、已知限制和回滚/恢复说明。
- 本人最低参与要求：确认阶段目标、查看核心差异、亲自运行验收、记录结果并理解架构影响。
- 项目达到稳定里程碑后，再集中学习完整调用链、面试考点和简历表达，不要求在 AI 编码时逐行手搓。

## 4. 月度路线图

### 2026 年 9 月剩余时间：完成计划切换与学习系统搭建

目标不是补齐大量新知识，而是把后续四个月的学习方式稳定下来。

- 建立 JVM、OS、计网和 Java 八股的 D+1、D+3、D+7、D+14 复习记录。
- 继续当前 MySQL 学习主线，完成事务、隔离级别、MVCC、锁之间的第一轮联系。
- OS 继续按照 JYY 课程顺序学习；计网完成 TCP 可靠传输和 TIME_WAIT 等已明确欠缺内容。
- JVM 开始第一轮入门，先建立运行时数据区、对象与内存、垃圾回收的整体地图，不急于背全部收集器参数。
- 算法保持节奏并开始记录陌生中等题的独立完成情况。
- 项目只完成 AI 优化任务的阶段划分、验收规则和优先级确认，不要求本月实施大规模重构。

月末验收重点：复习系统是否真的运行、课程负担下能够保持多少学习量、哪些任务频率需要调整。

### 2026 年 10 月：基础框架建立月

- Java 主线进入并发基础，联系线程、锁、线程池和 Java 内存模型的基本问题。
- JVM 建立运行时数据区、对象生命周期、类加载和 GC 第一轮框架。
- OS 按课程节奏推进，优先理解程序、系统调用、进程/线程和并发相关概念；不按面试词条跳课。
- 计网完成 TCP 可靠传输、流量/拥塞控制、HTTP/HTTPS 第一轮框架，并联系后端连接与超时。
- MySQL/Redis/Spring 按现有八股顺序持续推进和复习。
- 算法建立高频题型框架，开始统计陌生中等题在限时条件下的独立完成率，为后续机试做准备。
- Agent 项目最多推进一个 AI 优化阶段，优先选择边界清晰、可测试、不会引发全仓库大改的基础问题。

月末验收重点：能否脱稿解释本月核心知识，以及 D+7、D+14 后还保留多少，而不是统计看完多少视频。

### 2026 年 11 月：原理深化与后端联系月

- Java 并发与 JVM 继续深化，重点理解可见性、原子性、有序性、锁和线程池等内容之间的关系。
- OS 继续推进进程、调度、并发、同步或课程实际到达的章节，并至少完成一次动手观察或小实验。
- 计网推进 HTTP 连接管理、HTTPS/TLS、DNS、网络故障定位和 SSE/WebSocket 等后端相关主题。
- MySQL、Redis 和 Spring 从分散八股转向综合问题，例如事务、缓存一致性、并发更新和异常处理。
- 算法继续覆盖高频题型，并统计陌生中等题独立完成率和常见失败原因。
- 每周至少安排一次限时综合训练或模拟口述，练习在没有题解的情况下说明思路、复杂度和边界条件。
- Agent 项目视 10 月验收结果决定是否进入下一阶段；若上一阶段未稳定，不叠加新重构。

月末验收重点：能否把 JVM、OS、计网知识和 Java/项目中的具体现象联系起来。

### 2026 年 12 月：整合复习与负荷调整月

本月可能受六级、课程作业和期末复习影响，技术计划主动收缩，不追求大量新内容。

- JVM、OS、计网进行第一轮综合复习，整理长期不稳定的问题。
- Java、MySQL、Redis、Spring 以综合问答、错题和场景题为主，减少零散新专题。
- 算法保持最低连续性，课程密集日以复做为主。
- 项目原则上只做已开始阶段的验收、修复和文档收口，不新开大型功能。
- 在不影响六级和期末的前提下，开始收集下一阶段的大厂、中厂和高质量中小厂岗位要求，形成一版 JD 能力差距表；暂不要求集中投递。
- 根据实际考试安排，允许连续若干天执行最低版本，不将暂停的新内容累积成欠账。

月末验收重点：在学习时间减少时，哪些知识仍能保持，哪些内容需要寒假重新补强。

### 2027 年 1 月至寒假：学期验收与寒假转换

- 期末考试前以课程为主，技术学习保留到期复习和少量算法复做。
- 考试结束后完成 Java/JVM/OS/计网/数据库/算法的学期验收。
- 检查 Agent 项目的稳定版本、启动方式、测试结果、架构文档和本人掌握边界。
- 对黑马点评进行一次状态检查，决定寒假是否需要恢复和去教程化优化。
- 根据验收结果制定寒假详细计划：项目集中学习、简历制作、项目表达、模拟面试和小规模投递。
- 形成一版可继续修改的中文简历、项目贡献边界说明和目标公司分层表，为可能提前开放的实习岗位做好准备。

学期最终验收不以“全部学完”为标准，而以知识保留、独立解释、应用联系和下一阶段缺口是否明确为标准。

## 5. 每月详细计划的制定规则

每月开始后的前 1 至 2 天制定当月计划，输入包括：

1. 上月实际完成情况和未掌握内容。
2. 当月课程表、作业、期中/期末和六级压力。
3. 当前 OS、计网、JVM、Java 八股和算法进度。
4. 项目上一个 AI 优化阶段是否真正完成验收。

每个月只设置 3 至 5 个核心成果，并拆成每周目标。月计划应包含：

- 本月必做、选做和暂不做。
- 各知识主线的新内容范围。
- D+1、D+3、D+7、D+14 到期复习安排。
- 算法题型目标与复做目标。
- 最多一个项目优化里程碑。
- 课程密集周和考试周的降级方案。
- 月末验收题、复述或实际验证方式。

未完成任务不自动全部顺延。月末先判断它仍是否重要：重要且有前置价值的进入下月；收益下降或范围过大的任务删除、缩小或继续后置。

## 6. 寒假前转换条件

满足以下大部分条件后，寒假计划可以从“基础沉淀”转向“求职准备”：

- Java、JVM、MySQL、Redis、Spring 的核心问题能够完成第一轮脱稿回答。
- OS 与计网已经形成连续框架，不再只是零散名词。
- 算法常见题型能够识别，部分陌生中等题可在 30 至 40 分钟内独立完成，并能说明复杂度和边界条件；Hot 100/面试经典 150 的重点题已形成稳定复做记录。
- Agent 项目存在一个稳定、可重复启动和验证的版本。
- 能诚实说明课程代码、上游代码、AI 生成和本人参与的边界。
- 能讲清项目整体架构、主要链路、至少一个真实问题与验证过程。
- 寒假或大二下具备较稳定的线下到岗时间。

如果基础已经明显改善但项目尚未稳定，寒假优先收口项目；如果项目稳定但基础回答仍薄弱，寒假优先复习和模拟面试。是否投递由验收结果决定，不因进入寒假就自动海投。

## 7. 寒假及大二下的投递分层

投递时不再预设“只投中小厂”，采用三层组合：

1. 冲刺层：有合适实习岗位的大厂、头部互联网公司和技术要求较高的业务团队。即使成功率较低也正常投递，用于争取机会并获取高标准面试反馈。
2. 重点层：技术栈匹配、业务真实、能够接触正式研发流程且有代码评审或持续反馈的中厂和成长型公司。
3. 保底层：规模较小但岗位职责明确、确实参与开发、成本可覆盖且能形成可信经历的团队。

最终选择仍以岗位内容、导师或评审机制、真实项目参与、到岗要求、学习空间和生活成本为核心，不以“大厂”标签覆盖明显不合适的岗位。实际投递比例在寒假月计划中根据当时岗位数量、个人准备度和到岗条件确定。
