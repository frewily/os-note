最近感觉但凡简历上沾一点"Agent"俩字，面试官眼睛都会亮一下，然后开始连环追问……我也是被问了好几场之后才慢慢摸出点规律，不是网上那种复制粘贴的八股文，是真实被问到、也真实卡壳过的题，整理出来给准备面Agent方向的兄弟姐妹们避避坑。

## 一、题单先甩出来，按模块给大家拆一下

### 1️⃣ 基础认知类（上来先看你到底懂不懂）

- Agent和普通Chatbot、和传统RPA的本质区别是什么？
- 一个完整的Agent一般包含哪几个核心模块？（记忆、规划、工具调用、执行反馈这套说不清楚基本就凉半截）
- ReAct是什么，跟单纯的Function Calling有啥区别？
- Agent的"记忆"分哪几种？短期记忆和长期记忆分别怎么落地？

### 2️⃣ 框架与工程实现类

- LangChain / LangGraph / AutoGen / CrewAI 用过哪个？为什么选它，踩过什么坑？
- MCP协议是干嘛的，最近为什么突然这么火，解决了什么之前的痛点？
- Function Calling底层模型是怎么"决定"该调哪个工具、传什么参数的？
- 工具调用失败了怎么办？重试机制、超时机制怎么设计？

### 3️⃣ RAG / 知识增强类

- Agent里用的RAG和普通问答RAG有什么不一样（比如要不要多轮检索、什么时机触发检索）？
- 检索结果不准导致Agent决策跑偏，你怎么解决？
- Chunk怎么切效果比较好？有没有真的因为切分策略翻过车？

### 4️⃣ 多智能体协作类

- 什么场景下必须上Multi-Agent，单Agent搞不定？
- Agent之间怎么通信、怎么分工？听说过Orchestrator模式吗？
- 多个Agent互相"甩锅"进入死循环，怎么兜底？

### 5️⃣ 工程落地 / 稳定性类

- Agent的成本怎么控制（Token消耗、调用次数、模型选型分级）？
- 怎么评估一个Agent做得好不好，有哪些具体指标？
- Agent出现幻觉、瞎调工具，线上怎么兜底？
- 生产环境怎么做Agent的可观测性（日志、Trace、埋点）？

### 6️⃣ 系统设计类（压轴大题，基本必考）

- 设计一个智能客服/代码助手/数据分析Agent，讲讲你的整体架构
- 如果任务要跑几十步才能完成，怎么保证Agent不跑偏、不断链？

## 二、挑3道我印象最深的，展开讲讲回答思路

**题目1：ReAct和纯Function Calling到底有什么区别？** 回答思路：先说结论——ReAct是一种"思考-行动-观察"循环的范式，强调模型每一步都要显式输出推理过程（Thought），再决定要不要调用工具（Action），拿到结果后再反思（Observation）继续下一轮；而纯Function Calling更多是模型直接判断"该不该调、调哪个"，不强制暴露中间推理链路。可以补一句：ReAct更适合需要多步推理、容易出错要回头修正的复杂任务，Function Calling更适合单步、目标明确的调用场景，两者其实经常是搭配着用的，不是二选一。

**题目2：怎么评估一个Agent系统做得好不好？** 回答思路：不要只说"看效果好不好"这种空话，可以从几个维度拆开讲：任务完成率（有没有把活干完）、路径合理性（有没有绕远路、重复调用）、工具调用准确率、幻觉/瞎调用的比例、响应延迟和成本、以及人工评估+自动化评测（比如用另一个模型当裁判打分）结合的方式。能提一句"离线评测集+线上灰度反馈"闭环会明显加分。

**题目3：任务链很长（几十步）的Agent，怎么防止它跑偏或者死循环？** 回答思路：可以从几个手段讲：一是设置最大步数/最大工具调用次数硬性上限；二是引入阶段性检查点，定期让模型回顾目标、判断是否偏离；三是关键决策点加人工确认或者规则兜底；四是记忆管理上做摘要压缩，避免上下文塞太满导致模型"忘了自己在干嘛"。举个自己实际处理过的小例子会比干讲理论更有说服力。

## 三、最后反问环节，别只会说"暂时没有问题"

反问其实是变相考察你对这个方向的思考深度，参考几个方向：

- 团队现在Agent相关项目主要用的什么技术栈，是基于开源框架二次开发还是自研？
- 团队Agent项目现在处于什么阶段，是还在打磨demo，还是已经在生产环境跑量了？
- 平时怎么评估和监控Agent的效果，有没有专门的评测/回归体系？
- 这个岗位日常更偏算法调优（Prompt、模型选型），还是偏工程落地（稳定性、成本、可观测性）？

问出这几个问题基本能让面试官感觉到"这人是真的懂，不是背了几个术语来面试的"。
